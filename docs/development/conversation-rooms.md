# 대화별 저장과 전환

새 대화는 기존 대화를 보존한다. 왼쪽 목록에서 과거 질문, 답변, Run 참조를 다시 열 수 있다. 분석 화면에서는 **일반**과 **로컬**로 전환할 수 있다. 기존 대화에서 모드를 바꾸면 새 방을 열고 이전 방을 보존한다. 실행 모드 정보 없이 저장된 과거 대화는 읽기 전용이다.

## 저장 계약

- V12 마이그레이션은 현재 대화를 첫 채팅방으로 등록하고 기존 답변과 UI 스냅샷에 해당 방의 식별자를 붙인다. 저장된 본문과 수치를 다시 생성하지 않는다.
- `workspace_conversation`은 워크스페이스 수명과 `conversationEpoch` 조합으로 방을 식별한다. 선택한 Run의 고정 버전, 후보 참조 출처와 Agent 버전을 보존한다.
- `conversation_turn`과 기존 Agent 요청은 방별로 조회한다. 목록은 첫 질문을 제목으로 사용하며 별도의 LLM 호출을 하지 않는다.
- `POST /api/workspace/new-conversation`은 현재 방의 선택 상태를 저장하고 새 방을 만든다. `POST /api/workspace/conversations/{epoch}/activate`는 선택한 방을 복원한다. 두 요청 모두 기존 상태 토큰과 revision 검증을 적용한다.
- 새 대화 요청에 `decisionDemo: true`를 보내면 의사결정 시연방을 만들고 서버에서 표준 `v2`로 고정한다. V21은 방 목록에 시연방 구분을 추가한다. 의사결정 Agent 탭은 이 방을 열며 분석 대화 목록은 시연방을 표시하지 않는다. 의사결정 시연방은 표준 `v2`가 활성화된 배포에서만 만들 수 있다.
- 다른 방으로 이동해도 수락된 Agent 요청은 원래 방에서 계속 처리된다. 완료 시 요청에 저장된 방으로 답변을 기록하며, 현재 보고 있는 다른 방의 revision을 변경하지 않는다. 사용자 확인 대기도 원래 방으로 돌아와 이어갈 수 있다.
- Run 삭제는 현재 방과 보관된 방의 입력용 참조를 함께 정리한다. 과거 답변 스냅샷은 보존한다.
- 전체 초기화는 저장된 방 전체와 판단 기록을 지운다. 초기화 안내도 이 범위를 표시한다. 등록된 Run과 원본 파일의 보존 정책은 기존 계약을 따른다.

브라우저의 전송 중 응답과 UI 저장 응답은 기존 generation 검사와 직렬화 큐로 관리한다. 방을 바꾼 뒤 도착한 응답을 새 방에 합치지 않는다. 아직 보내지 않은 입력문은 Agent 화면을 유지한 채 방을 오갈 때 방별로 유지하며, 화면을 다시 불러오거나 전체 초기화하면 비운다.

의사결정 시연은 비전공자의 목표를 지표로 풀어 보여주고 사용자에게 승인받는다. 표준 V2가 후보를 검색하고 결과를 분석한다. UI는 승인 조건에 일치하는 후보 표와 바이어스 전력 비교 차트를 표시하고, V2에 후속 질문을 보내면 동일한 Run 버전 집합이 확인된 뒤 장단점 표를 표시한다. V2의 해석은 검토를 통과했을 때 표시한다. V2 검색 결과는 시연방에 저장되며, 목표 카드와 최종 후보 선택은 새로고침 시 초기화된다.

분석 Agent와 동일하게 채팅 입력창에서 `@`를 입력해 기준 Run을 붙인다. 시연방에서는 Run 하나를 기준으로 하며 새 태그를 붙이면 기존 태그를 교체한다.

로컬 미리보기는 `npm run dev:decision-demo`로 실행한다. JDK 21, Docker, Node, 잠금 파일의 Python 환경과 V2 토크나이저가 필요하다. 스크립트는 별도 테스트 DB와 프런트엔드 포트를 선택하고 접속 주소를 출력한다. 인공 Run을 사용하고 테스트용 계획 모델로 표준 V2를 실행한다. 미리보기에서는 기본 기준 Run의 손상 줄이기 경로에 후보가 세 개 있다.
