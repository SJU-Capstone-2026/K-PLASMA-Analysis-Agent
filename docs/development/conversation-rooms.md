# 대화별 저장과 전환

2026-11-05 사용자 요청으로 새 대화의 동작을 변경했다. 새 대화는 기존 대화를 보존하며, 왼쪽 메뉴에서 이전 대화로 돌아갈 수 있다. Agent 화면은 최대 850px 폭을 사용하고, 오른쪽 패널이 없는 현재 화면에서는 남는 폭을 좌우에 나누어 배치한다.

## 저장 계약

- V12 마이그레이션은 현재 대화를 첫 채팅방으로 등록하고 기존 답변과 UI 스냅샷에 해당 방의 식별자를 붙인다. 저장된 본문과 수치를 다시 생성하지 않는다.
- `workspace_conversation`은 워크스페이스 수명과 `conversationEpoch` 조합으로 방을 식별한다. 선택한 Run의 고정 버전, 후보 참조 출처와 Agent 버전을 보존한다.
- `conversation_turn`과 기존 Agent 요청은 방별로 조회한다. 목록은 첫 질문을 제목으로 사용하며 별도의 LLM 호출을 하지 않는다.
- `POST /api/workspace/new-conversation`은 현재 방의 선택 상태를 저장하고 새 방을 만든다. `POST /api/workspace/conversations/{epoch}/activate`는 선택한 방을 복원한다. 두 요청 모두 기존 상태 토큰과 revision 검증을 적용한다.
- 다른 방으로 이동해도 수락된 Agent 요청은 원래 방에서 계속 처리된다. 완료 시 요청에 저장된 방으로 답변을 기록하며, 현재 보고 있는 다른 방의 revision을 변경하지 않는다. 사용자 확인 대기도 원래 방으로 돌아와 이어갈 수 있다.
- Run 삭제는 현재 방과 보관된 방의 입력용 참조를 함께 정리한다. 과거 답변 스냅샷은 보존한다.
- 전체 초기화는 저장된 방 전체와 판단 기록을 지운다. 초기화 안내도 이 범위를 표시한다. 등록된 Run과 원본 파일의 보존 정책은 기존 계약을 따른다.

브라우저의 전송 중 응답과 UI 저장 응답은 기존 generation 검사와 직렬화 큐로 관리한다. 방을 바꾼 뒤 도착한 응답을 새 방에 합치지 않는다. 아직 보내지 않은 입력문은 Agent 화면을 유지한 채 방을 오갈 때 방별로 유지하며, 화면을 다시 불러오거나 전체 초기화하면 비운다.
