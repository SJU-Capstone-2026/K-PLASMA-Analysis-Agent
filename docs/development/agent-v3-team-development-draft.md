# Agent v3 팀 개발 규칙 — 초안

작성일: 2026-11-11. 사용자가 선택한 방향은 **현재 v2 보존, v2 에이전트 구현의 실제 복제,
독립된 v3에서 규칙 기반만 사용한 경우와 RAG까지 추가한 경우 비교**다.
이 문서는 협업 규칙 초안이며 독립 복제 방향은 사용자가 승인했다. 첫 작업은 복제·동일 동작 검증까지만 수행한다.
서버·DB·UI의 v3 활성화와 규칙 기반·RAG·ON/OFF 구현은 후속 범위다.

## 1. 버전과 보존 기준

| 대상 | 역할 | 변경 원칙 |
| --- | --- | --- |
| 현재 v2 | 기존 복합 도구 성능의 기준판 | 새 규칙 기반·RAG 기능을 추가하지 않는다 |
| v3 | v2를 실제 복제한 새 에이전트 | 규칙 기반과 RAG의 통합·ON/OFF·비교를 여기에서 개발한다 |
| v1의 개발 중 기능 | 단일 기능 검증 환경 | 검증한 로직을 v3로 이식하되 복합 실행 검증은 새로 한다 |

첫 독립 복제의 v2 코드 기준은 PR #33의 검증된 코드 커밋 `51d077c9878b635c96da709eb7eb2aefd36699e1`이다.
3회차 유료 평가 소스는 `eff226944dd0e01e201d81556173d105e7b4c4b9`이므로 두 기록을 혼동하지 않는다.
복제 작업은 기준 SHA·잠금 파일·프롬프트·스키마·모델 설정과 원본 파일 해시를 manifest에 고정한다.
이 문서 작성만으로 태그 생성이나 v2 변경을 수행한 것은 아니다.

그래프 버전, 계획 스키마 버전, 답변 스키마 버전은 별개다. 기존 `agent-answer-v3` 계약은
답변 스키마 이름이며 이번에 만들 그래프 v3가 이미 구현됐다는 뜻이 아니다.

## 2. 실제 복제와 공유 금지 범위

v3는 고정한 v2 보존본에서 실제 복제한다. v2 그래프를 호출하는 wrapper나 공통 노드 조합으로 만들지 않는다.
다음 에이전트 내부 구현을 실제로 복제하고 v3 전용 소스로 유지한다.

| 복제 대상 | 규칙 |
| --- | --- |
| 그래프·노드·분기·상태·예산 | v3에서 독립적으로 수정한다 |
| 계획·재계획·답변·검토 프롬프트와 모델 설정 해석 | v2의 지시문·설정을 import해서 공유하지 않는다 |
| 계획·답변 계약, 입력 연결, 코드·의미 검증 | v3 전용 계약과 구현을 둔다 |
| executor, 수치·조회·비교·설명 도구와 내부 도메인 helper | 같은 함수·객체를 v2와 공유하지 않는다 |
| 모델/API 호출, 진행 이벤트, 관측·체크포인트 adapter | 에이전트 내부 adapter 구현도 v3 쪽으로 복제한다 |

표준 라이브러리·외부 패키지는 같은 잠금 버전을 사용할 수 있다. 서버·DB 엔진·인증·기존 Run API·
공통 화면 틀은 제품 기반으로 재사용할 수 있지만, 이는 에이전트 노드·업무 구현 공유를 뜻하지 않는다.
버전 선택 진입점은 각 버전의 독립 실행기로 보내는 역할만 맡는다.
v3의 새 계약·저장·화면 동작은 버전으로 분리하고 기존 v2 계약·렌더링·체크포인트 해석을 바꾸지 않는다.

v2↔v3 내부 import, 공통 업무 모듈로의 재통합, 같은 노드 함수 등록을 금지한다.
v1의 개발 중 기능도 필요한 로직을 v3 소유로 이식하며 v1 그래프를 실행 중 호출하지 않는다.
공통 버그를 발견해도 다른 버전에 자동 반영하지 않는다. 필요한 수정은 버전별 PR과 검증을 거친다.
v2 기준판 수정이 필요하면 별도 합의로 새 기준을 만들고 원래 보존본은 유지한다.

## 3. v3의 비교 모드

| 모드 | 새 규칙 기반 기능 | RAG | 용도 |
| --- | --- | --- | --- |
| 도구 추가 전 | OFF | OFF | 복제 후 기존 v2 동작과의 대응 확인 |
| 규칙 기반만 | ON | OFF | 주요 비교 조건 A |
| 규칙 기반 + RAG | ON | ON | 같은 질문의 주요 비교 조건 B |

RAG 단독 모드는 이번 필수 비교 범위에 넣지 않는다. 주요 비교는 A/B이며 v2는 보존 기준이다.
RAG가 규칙 기반의 결과에 어떤 방식으로 근거를 추가·보완하는지 계약에 명시한다.
RAG가 숫자 경계·Run 버전·사용자 선택·확정 제외 조건을 임의로 완화해서는 안 된다.

OFF인 기능의 실행을 차단하고 호출 수 0을 확인한다. 비활성 도구는 계획에 노출하지 않는다.
하나의 통합 도구 안에서 검색 전략을 바꾸는 설계라면 규칙 기반 기능은 유지할 수 있지만,
RAG OFF에서 RAG 호출·검색 근거·RAG 전용 기능 설명이 남지 않게 한다.
통합 도구 하나로 둘지 별도 도구로 둘지는 구현 설계에서 확정하되 A/B의 업무 목표와 정답 기준은 같아야 한다.

버전·모드·설정 digest는 요청 시작 시 저장하고 HITL·재계획·재작성·재시작에도 유지한다.
대기 중인 요청에 새 환경변수나 UI 토글을 소급 적용하지 않는다.

## 4. 역할과 PR 절차

| 역할 | 책임 |
| --- | --- |
| 그래프·통합 담당 | 독립 복제, 버전 연결, 복합 실행, 요청별 모드 보존 |
| 규칙 기반 담당 | 규칙·불확실 판정·경계와 근거의 인공 계약 테스트 |
| RAG 담당 | 문서·메모 검색, 인덱스 버전, 근거 반환, 실패·0건 구분 |
| 평가·검수 담당 | 독립 정답, 동결 문항, A/B 실행 목록, 답변·화면 검토와 요약 |

한 사람이 여러 역할을 맡을 수 있다. 실제 담당자와 리뷰어는 팀이 정하며 임의로 배정하지 않는다.

- 최신 main에서 역할별 작업 브랜치를 만들고 같은 공유 브랜치에 함께 직접 수정하지 않는다.
- 초기 분리 PR은 v2 보존·v3 복제·버전 연결을 담당한다. 규칙 기반, RAG, 복합 통합은 작은 후속 PR로 나눈다.
- 공통 입력·출력 계약을 먼저 합의한다. 생산자·소비자·계획·검토·저장·화면·문서·테스트를 함께 갱신한다.
- 작성자 외 팀원 1명 이상이 승인한다. 그래프·계약 변경은 관련 기능 담당자도 리뷰한다.
- v3를 추가하려면 서버 허용 버전, DB 제약, worker 라우팅, 공통 타입, UI 선택·저장까지 갱신한다.
현재는 v1/v2만 지원하므로 그래프 파일만 복사해서 전체 v3 통합이 완료됐다고 보지 않는다.

이번 1단계는 독립 에이전트 모듈 복제와 메모리 그래프의 동일 동작 검증까지다.
버전 식별·모듈 경로·v3 전용 설정 이름 외에는 원본 로직·프롬프트·수치·예산을 바꾸지 않는다.
서버·DB·UI 등록을 포함하는 활성화는 별도 PR로 수행한다. [복제 실행 계획](../superpowers/plans/2026-11-11-agent-v3-independent-clone.md)에 첫 단계의 완료 조건을 기록한다.

## 5. 병합 전 검증

1. 보존 manifest와 비교해 v2 에이전트 내부 파일이 바뀌지 않았는지 확인한다.
2. v3의 금지된 내부 공유·import가 없고 상태·실행·체크포인트가 버전 간 섞이지 않는지 확인한다.
3. 고정 모델 응답과 인공 데이터로 복제 전후 수치·단위·결과 순서·직렬화·HITL·복구를 대조한다.
4. ON/OFF 노출·호출·저장과 오류 처리를 검사한다. 실행 실패를 빈 검색이나 가짜 성공으로 바꾸지 않는다.
5. 실제 Agent 평가에는 계획 Decisions ON, 재계획 최대 2회·재작성 최대 1회를 유지한다.
6. 화면 변경은 390/800/1008/1440px에서 표·그래프·선택창·진행·새로고침 복원을 확인한다.

CI는 인공 응답 기반 검사만 수행한다. 유료 A/B 평가는 [비교 실험 방법 초안](agent-v3-evaluation-method-draft.md)에
따라 별도로 범위·횟수를 정해 실행한다. 단독 도구 통과를 복합 Agent 통과로 보고하지 않는다.

## 6. 기록과 남은 결정

내부 평가 집계·설정·재현 방법·실패 요약은 공개 문서와 PR에 남긴다.
물리 실험 파일·실제 Run payload·DB 백업·사용자 원문과 이를 포함한 원시 평가 자료는 로컬에 둔다.

구현 전 확정할 항목은 담당자, 보존 manifest 범위, 통합 도구 계약, RAG 근거 채택·충돌 처리,
인덱스 버전, 신규 평가 문항·횟수·허용 회귀 기준이다. 이 문서는 해당 구현이 끝났다는 보고서가 아니다.
