# LocalLLM v2.3: d1 MLX 8비트 개별 처리와 검토 입력 개선

## Goal Capsule

**쉽게 읽는 요약:** d1을 MLX 8비트로 실행하고, 검사 하나씩 차례대로 검토한다. 같은 인공 계획 5개로 정밀도 변경 → 고정 지침 영어화 → 반복 설명 축약 → 실행 정리표 제외의 영향을 따로 비교한다. 질문·원본 계획·검사항목·그래프·최종 응답은 유지한다.

이 문서는 사용자의 최신 v2.3 구현·실험 요청을 반영한다. [이전 입력 축약 계획](2026-11-15-002-local-llm-d1-review-input.md)의 기존 Q8 llama.cpp 유지·영어화 제외·정리표 일부 유지·큰 평가 집합은 이번 범위에서 대체한다. 과거 검증 결과와 문서는 당시 기록으로 보존한다. 이번 변경은 별도 v2.4가 아닌 **v2.3**에 포함한다.

- 목표: M4 Pro 24GB에서 d1 가중치 메모리와 검사 입력을 줄이고, 정확도·시간·메모리 변화를 함께 확인한다. 속도·정확도 유지 여부는 측정 전 확정하지 않는다.
- 고정 조건: Docker VM 1536MiB, d1 계획 검토 ON, 기존 그래프·응답·저장 계약, 요청 전체 재계획 최대 2회·필요한 답변 검토와 재작성 최대 1회.
- 실행 범위: 로컬 변환·구현·CPU 검증·아래 제한된 인공 모델 실험. 상용 API 비교·40문항 웹/API 재평가·추가 모델 탐색·commit/push/PR은 자동 후속 작업에 포함하지 않는다.

## Product Contract

### R1. 동일한 검토를 한 항목씩 실행

`D1_ENGINE=mlx`, `D1_GROUP_SIZE=1`, `D1_INDEPENDENT_BATCH_SIZE=1`을 사용한다. 한 검토 HTTP 요청에는 여러 검사가 들어갈 수 있지만 모델은 각 검사를 독립 입력으로 하나씩 순차 처리한다. 검사 ID·개수·순서·선택 ID·응답 완전성 검사·PASS/ISSUE/UNCLEAR/UNAVAILABLE 집계·확률 해석·보정은 유지한다.

d1의 이전 llama.cpp Q8_0·공동 입력16·독립 병렬4 실행 코드는 제거한다. 같은 서비스의 **MLX BF16 개별 처리**는 비교·복구 경로로 남긴다. Qwen의 llama.cpp·native `submit_plan`·생각 설정·계획 캐시는 변경하지 않는다. 후보가 실패해도 BF16이나 원격 모델로 자동 우회하지 않는다.

### R2. 같은 원본에서 MLX용 8비트 파일 생성

고정한 `LiquidAI/d1-2B` BF16 snapshot에서 **MLX affine 8비트, group size64**로 eligible Linear 153개만 변환한다. tied embedding·norm·convolution은 BF16으로 유지한다. 기존 GGUF Q8_0와 다른 파일 형식·양자화 규칙이므로 이를 동일한 Q8 결과라고 합치지 않는다.

원본 revision·tokenizer·calibration·공식 readout·temperature·attention mask·singleton 의미는 유지한다. pinned `mlx-decision` 1.3.0 commit `2527a733c97a3fd5e0de54ea19f74fd362ed1ad2`와 MLX 0.32.4를 사용하며 설치 라이브러리를 수정하지 않는다. 별도 MLX 가상환경은 공유 worker 환경과 분리한다.

변환은 로컬 경로만 받는다. 원본 manifest·파일 SHA를 확인하고 비어 있는 폴더를 포함해 이미 존재하는 출력 경로를 거부한다. 새 임시 폴더에서 완료한 뒤 최종 폴더로 원자적으로 옮긴다. config의 정확한 quantization spec·Linear 경로, schema1 manifest의 원본 revision·변환 파일 SHA·source manifest SHA를 기록한다. 원본 파일은 덮어쓰지 않는다.

### R3. 고정 설명만 영어로, 중복만 축약

- 사용자 질문·대화·확정 문맥·Qwen 원본 계획·원문 인용·답변·실행 근거는 번역·요약·잘라내기 없이 보존한다.
- 영어화는 고정 검토 지침·검사 설명·선택지 설명·정책·도구 계약·지표 label/정의에 한정한다. 내부 필드명·도구명·검사 ID·선택 ID·단위·경계·의존성 의미는 보존한다. 답변 검토의 고정 지시도 같은 원칙으로 영어화한다.
- 반복 지표 정의는 공통 사전과 참조로 제공한다. 32개 지표 모두의 이름·label·unit·plotId·정의가 복원되어야 하며 비슷해 보이는 다른 정의를 합치지 않는다.
- `plan_digest`·`input_digest`는 d1 전송에서만 제외하고 추적·결과 매칭·원본 snapshot에는 남긴다.
- 마지막 구성은 전송용 `execution_view`를 제외한다. 원본 계획·`check_specs`·`program_effects`를 남기고, 저장 snapshot의 원래 정리표는 지우지 않는다.
- projection은 원본을 mutate하지 않는다. 계수 입력과 실제 POST에 같은 projection을 사용하고, 파싱·근거 매칭·재계획 피드백은 원본 context를 기준으로 한다. 알 수 없는 표현·계약 변경은 조용한 fallback 대신 오류로 보고한다.

### R4. 보호 범위와 준비 판정

`v2_localLLM` 그래프 노드·분기·HITL·도구 실행·계획 schema·최종 응답 schema·SSE·DB·과거 대화·판단 snapshot은 유지한다. v2·v3는 수정·평가하지 않는다. 설정 precision·입력 표현 버전/소스 hash·변환 helper·모델/라이브러리 파일 SHA를 fingerprint와 준비 증거에 연결한다. 기존 프로필의 메모리 증거나 미완료 checkpoint를 새 프로필로 강제 재사용하지 않는다.

실제 평가 전 모델 설정과 실제 그래프 상태의 `plan_review_enabled=true`를 확인한다. 꺼져 있으면 중단한다. 로컬 token 인증·literal loopback·proxy/redirect 거부·cloud fallback 금지를 유지한다. 업데이트·모델 다운로드를 위한 일반 인터넷은 허용하고 OS 수준 송신 차단은 추가하지 않는다.

Docker VM 1.5GiB에서 기존 DB·볼륨·Run을 유지한다. development 정책은 warning·swap 증가를 기록하면서 허용하고 critical·알 수 없는 압력·모델 해제 실패는 다음 모델 호출을 차단한다. Qwen sleep 확인 → d1 load/review/unload 확인 → Qwen wake의 순차 상주를 유지한다. 다른 앱을 임의로 종료하지 않는다.

## Planning Contract

### 5개 비교 구성

모든 구성은 같은 고정 인공 계획 5개와 같은 기대 판정·검사 수를 사용한다. Qwen의 계획을 구성마다 새로 생성하지 않는다.

| phase | MLX 정밀도 | 입력 프로필 | 확인하는 차이 |
|---|---|---|---|
| `bf16-baseline` | BF16 | `ko-full` | 보존하는 MLX 개별 기준 |
| `q8-baseline` | affine8/group64 | `ko-full` | 양자화 영향 |
| `q8-english` | affine8/group64 | `en-full` | 고정 설명 영어화 영향 |
| `q8-compact` | affine8/group64 | `en-compact` | 반복 정의 공통화·전송 hash 제외 영향 |
| `q8-no-view` | affine8/group64 | `en-compact-no-view` | 전송 실행 정리표 제외 영향 |

worker 기본 후보는 `q8` + `en-compact-no-view`다. BF16 alias는 `LiquidAI/d1-2B:BF16`, Q8 alias는 `LiquidAI/d1-2B:MLX8`이며 서비스와 worker의 정밀도·모델 폴더를 함께 맞춘다. 기본 설정이 존재하는 것과 실제 준비·품질 관문 통과는 별개다.

### 실행 예산

| 단계 | 실제 추론 HTTP 요청 상한 | 범위 |
|---|---:|---|
| 구성 비교 | 25 | 5구성 × 같은 계획 5개 × 1회 |
| 전체 스택 메모리 준비 | 7 | Qwen 4 + d1 3 |
| 필요 시 최종 worker readiness | 4 | Qwen 3 + d1 1 |
| 합계 | **36** | 위 단계 외 자동 추론 없음 |

검토 요청 안의 개별 검사 추론 수는 별도로 보고한다. native token count 호출은 모델 생성/검토 요청과 구분해 기록한다. preflight는 artifact·live runtime 사실·실제 그래프 상태를 확인하며 숨은 `Settings.readiness()` 추론이나 warmup을 실행하지 않는다. 다른 phase로 바꿀 때마다 worker를 시작해 같은 준비 추론을 반복하지 않는다.

5개 계획은 정상과 오류를 포함한 인공 자료로 고정하고 실험 중 결과를 보고 교체·수정하지 않는다. 요청 실패도 횟수에 포함한다. 자동 반복·추가 튜닝·72건 평가·기존 상용 비교 재실행은 하지 않는다. critical·해제 실패·계약 오류가 발생하면 남은 실행을 멈추고 수행한 수와 미실행 범위를 보고한다.

### 측정·판정 기준

- **입력량:** 각 구성의 실제 native count로 검사별 전체 입력을 센다. 공통 본문만의 토큰이 아니라 검사지침·선택지·template을 포함한다. 평균은 `전체 검사 입력 토큰 합 / 전체 검사 수 합`이며 케이스별 평균을 단순 평균하지 않는다. 직전 구성 대비와 BF16/한국어 기준 대비 절감량·비율을 함께 제시한다.
- **정확도:** 기존 기대 상태와 검사별 올바른 선택·이유를 함께 확인한다. 상태만 ISSUE이고 이유가 틀린 경우도 표시한다. 기존 오답 개선과 새 오승인·오반려·불명확 증가를 상쇄하지 않는다. 검사 순서·응답 완전성·누락/잘림도 비교한다.
- **시간:** HTTP wall time, 실제 backend/model 처리 시간, 토큰 계수·load/unload 등 관측 가능한 단계를 구분한다. 5개 합계·요청당 평균·검사당 평균을 보고하며 대기/준비 시간을 추론 속도로 합치지 않는다.
- **메모리:** 모델/전체 시스템 피크·pressure 표본·swap 변화·해제 후 상태·Docker/DB OOM을 기록한다. 압축 파일 크기를 실행 메모리 피크로 대체하지 않는다.
- **해석:** 과거 Q8 llama.cpp 측정은 역사적 참고이며 이번 MLX BF16→MLX Q8의 동일 조건 비교와 섞지 않는다. 각 입력 1회뿐이므로 결과를 통계적 속도 향상이나 전체 질문 정확도 동등성의 증명으로 표현하지 않는다.

새 정확도 회귀·불완전 응답·메모리 차단이 있으면 통과로 보고하지 않는다. 단축 효과가 작아도 그대로 보고하며 검토 생략·추가 요약·후속 모델 호출로 결과를 보정하지 않는다. 실제 그래프 평가를 했다면 최초 계획 통과·Decisions 지적·재계획 뒤 최종 결과를 분리한다. 이번 고정 계획 비교는 웹 전체 성공률과 다른 지표다.

## Implementation Units

### U1. 로컬 MLX 양자화와 안전한 로더

`agent/python/runtimes/d1_mlx/weights.py`, `convert.py`, `service.py`에서 pinned 공식 BF16 로딩과 MLX affine8 compact tensor의 strict 로딩을 연결한다. tokenizer·tied embedding readout을 유지하고 새 manifest/정밀도를 검증한다. CPU 합성 header와 loader 계약 테스트를 먼저 사용하고 실제 변환·모델 실행은 메모리 감시와 모델 잠금 아래 따로 수행한다.

### U2. 입력 projection과 구형 d1 경로 정리

로컬 `core/d1_input.py`, `core/decisions.py`, `core/model_gateway.py`, `config.py`, `runtime.py`와 MLX 서비스/잠금/측정 연동을 갱신한다. 4개 입력 프로필을 같은 token guard·POST 경로에 연결하고 config/runtime 증거를 정밀도·표현과 묶는다. 구형 d1 실행·공동16·독립4 전용 분기를 정리하되 Qwen llama.cpp와 MLX BF16 singleton은 보존한다.

원본 불변·32지표 복원·영어화 범위·snapshot/digest 보존·계수/전송 일치·정밀도 alias·잘못된 설정 거부·동일 그래프/응답을 CPU 테스트로 확인한다. clone의 frozen baseline은 바꾸지 않고 현재 의도적 차이 목록만 맞춘다.

### U3. 제한된 인공 비교와 준비

`agent/python/evals/local_llm_d1_v23_probe.py`는 위 5개 phase 중 하나만 명시적으로 받으며 env의 precision/input profile이 다르면 실행하지 않는다. 같은 5개 인공 계획·기대 판정을 사용하고 overwrite 없는 비공개 출력에 결과를 기록한다. 단계 진행은 비공개 controller에서 관리하고 공개 CLI에 자동 전체 반복 옵션을 추가하지 않는다.

원시 출력·env·계획/지침 원문은 `.local/runtime/v2.3-mlx8-single/` 아래 Git 제외로 보관한다. 수행 요청 수·검사 수·토큰·판정·시간·메모리를 보고하며 준비 7개와 필요 readiness 최대4개도 따로 집계한다. 새 결과를 얻기 전에는 개선 수치를 문서에 쓰지 않는다.

### U4. 현재 실행 문서와 설정 예시

`.env.local-llm.example`과 [개발 가이드](../development/agent-v2-local-llm.md)를 현재 MLX Q8 개별·Docker1536MiB 기준으로 맞춘다. BF16 비교 설정·5개 phase·추론 예산·전송 범위·준비 관문을 쉽게 설명하고, 예전 검증 문서는 수정하지 않고 링크로 남긴다.

## Verification Contract

1. 모델 없는 단위 검증: 변환 metadata/header·원본 보존·strict loader, 4개 입력 projection과 32지표 보존, native token count/POST 일치, singleton만 허용하는 config/service, provenance·graph/응답 계약을 확인한다. Ruff/mypy와 변경 영향 범위 검사를 수행한다.
2. 로컬 자원 확인: Docker1536MiB·기존 DB 보존·review ON·프로세스 간 모델 잠금을 확인한다. 실제 변환과 실행을 다른 작업과 겹치지 않는다.
3. 모델 비교: 같은 5인공 계획에 5개 phase를 1회씩 실행하고 지정한 토큰 분모·정확도·시간·메모리를 보고한다. 실패한 요청도 기록한다.
4. 준비 증거: 추가7요청 메모리 검사와 필요 시 최대4요청 worker 준비를 상한 안에서 수행한다. 과거 준비 보고서나 cloud 결과를 새 후보의 통과 증거로 대신하지 않는다.
5. 보고: 집계·설정·재현 방법·실패 원인은 공유 문서에 남길 수 있지만 실험/DB/질문 원문·비밀값·원시 로그는 공개하지 않는다. 수행하지 않은 평가를 통과로 표시하지 않는다.

## Definition of Done

- d1은 MLX Q8 개별로 연결되고 MLX BF16 개별 비교가 가능하며, 구형 d1 실행 분기가 정리되어 있다.
- 고정 설명 영어화·정의 중복 축약·전송 `execution_view` 제외를 분리해 비교할 수 있고 원본·32지표·검사항목·그래프·응답 양식은 보존된다.
- 의미 있는 CPU 검증과 실행 가능한 설정 예시가 있으며, 실제 요청 수가 제한 안에서 집계되어 있다.
- 각 구성의 검사당 평균 토큰·정확도와 회귀·시간·메모리 및 미실행 범위가 보고된다. 결과가 나쁘거나 준비가 막힌 경우도 그 상태와 이유를 그대로 남긴다.
