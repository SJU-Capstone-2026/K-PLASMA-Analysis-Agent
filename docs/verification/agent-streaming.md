# Agent 진행 기록·답변 스트리밍 검증

2026-11-06, `feat/agent-graph-v2`의 로컬 작업 트리에서 확인했다. 기존 v2 구현과 UI 변경이 포함된 작업 트리이므로 이 기록은 스트리밍 변경과 그 회귀 검사 범위를 설명한다. 계획서는 `docs/plans/2026-11-05-001-feat-agent-progress-and-answer-streaming-plan.md`다.

## 확인한 동작

- 실제 실행 단계만 작은 진행 기록에 표시하고, 완료 시 실행 시간과 구분선으로 접는다.
- 제공자의 실제 출력 조각을 전송한다. v2 구조화 JSON은 본문으로 노출하지 않고, 검증된 수치·단위 치환과 수식 렌더링을 유지한다.
- 검증된 도구 표·그래프를 먼저 표시하고, 해석 작성·검토·재작성 중에도 유지한다.
- 재작성 시 기존 해석을 비우고 수정문을 다시 스트리밍한다. 잘못된 초안의 무효화와 기존 유효 초안 복원도 모델을 추가 호출하지 않고 처리한다.
- 단순 v2 조회·비교는 작성 모델·Decisions를 생략한다.
- 이벤트 순번 재생, 중복 키, 만료 lease, 요청·채팅방 revision, 취소·초기화 후 늦은 전송을 검사한다. 결과 공개 시 현재 계획의 실행 참조와 허용 필드만 사용한다.
- 새로고침·방 이동 복원은 추가 제출이나 모델 재실행 없이 이루어진다. 사용자 선택 대기에는 SSE 재연결을 반복하지 않는다.
- 390 / 800 / 1008 / 1440px에서 진행·수정·완료 UI와 가로 넘침을 확인한다. 수식의 지연 렌더링으로 높이가 늘어나는 경우를 포함해 최신 답변 따라가기와 이전 대화 위치 유지를 검사한다.

## 실제 웹·provider 검사

로컬 백엔드·프론트엔드·worker를 재실행한 뒤 기존 채팅방 3개와 기존 메시지 4개의 ID 보존을 확인했다. 브라우저에서 v1 일반 개념, v2 검색 후 전체 비교, v2 비교 후 경향 해석, v2 일반 개념의 네 요청을 실행했다. 실제 실험 값·전체 답변·요청별 원본 로그·스크린샷은 Git에서 제외한 로컬 경로에만 남겼다.

아래의 첫 본문 시간은 요청 접수에서 첫 공개 `answer.delta`까지이며, 완료 시간은 서버 RUNNING 누적 시간이다. 큐 대기 포함 여부가 달라 두 열의 차이를 순수한 검토 시간으로 해석하면 안 된다. 각 1회 관측이며 모델 속도 개선을 증명하는 전후 평균 비교는 아니다.

| 실제 웹 요청 | 첫 본문 | RUNNING 시간 | 확인 결과 |
|---|---:|---:|---|
| v1 이온 플럭스 개념·공식 | 6.36초 | 11.96초 | 본문 60조각 전송, 수식 렌더링, 완료 시간 복원 |
| v2 에너지 범위 검색 후 압력·Flux 비교 | 해당 없음 | 5.96초 | 계획 모델 1회, 실행 도구 2단계, 작성·Decisions 생략, 검증된 비교 표·그래프 표시 |
| v2 같은 비교에 경향 해석 추가 | 12.54초 | 28.86초 | 최초·수정 해석 전송과 초안 무효화 확인. 의미 검토는 ISSUE이며 아래 한계 참조 |
| v2 이온 플럭스 일반 개념·공식 | 6.33초 | 6.69초 | 본문 11조각 전송, 수식 렌더링, Decisions 생략 |

별도 provider 검사에서는 설정된 답변 모델의 실제 SDK 스트림을 1회 호출해 첫 텍스트 1.89초, 전체 응답 2.64초와 유효한 최종 구조화 응답을 확인했다. 이 검사는 모델 요청만 측정하므로 위 Agent 전체 시간과 직접 비교하지 않는다. 검사 당시 계획 모델은 기존 v2 설정, 답변 모델은 기존 `gpt-5.6-luna` / `none` 설정을 유지했다. 모델 변경이나 진행 문구용 추가 호출은 하지 않았다.

## 발견한 기존 해석 한계

검색 결과 전체를 비교하는 일부 경로에서는 `graphs/v2.py`의 `answer_evidence`가 Run별 관측값을 제외하고 범위 요약만 작성 모델에 전달한다. 표는 전체 도구 결과로 그리기 때문에 값이 보이지만, 해석 모델은 그 값의 대응표를 받지 못할 수 있다. 이번 실제 경향 해석 요청에서도 표에는 Run별 값이 있는데 본문은 그 값이 제공되지 않았다고 설명했다.

이 요청의 최초 해석은 서로 단위가 다른 지표의 범위 폭을 직접 비교하는 과장도 포함해 Decisions가 ISSUE를 반환했다. 수정 초안은 코드 검증을 통과하지 못했고, 기존 최종 표시 정책에 따라 마지막 코드 유효 초안을 복원했다. 따라서 이 사례를 의미 검토 통과로 기록하지 않는다. 스트리밍 전송·수정 경로는 동작했지만 해석 품질에는 별도 수정이 필요하다.

범위 요약 선택은 이번 스트리밍 구현에서 도입하거나 바꾸지 않았다. 후속 개선은 작성 모델에 어떤 Run별 근거를 제공할지와 요청별 해석 범위를 먼저 정해야 하며, 화면에서 경고를 숨기거나 잘못된 주장을 정규식으로 지우는 방식으로 처리하지 않는다.

## 진행 기록·정지 버튼 UI 후속 확인 (2026-11-06)

진행 기록과 완료 시간의 글씨를 사용자 채팅 본문과 같은 16px로 맞췄다. RUNNING·QUEUED의 별도 취소 버튼을 입력창의 사각형 정지 버튼으로 옮겼다. 중지 요청 중에는 중복 클릭을 막고, 다음 질문 초안은 보존한다. 사용자 선택 대기는 기존 취소 UI를 유지한다.

프론트엔드 244개 검사와 브라우저 8개 시나리오가 통과했다. 브라우저에서는 390 / 800 / 1008 / 1440px에서 본문과 진행 기록의 실제 계산된 글씨 크기가 같은지 확인했고, 입력창 정지 버튼을 통한 취소·늦은 조각 무시·새로고침 복원을 검증했다. 실제 로컬 v2 질문에서도 두 글씨 크기 16px와 입력창의 정지 버튼 1개를 확인하고, 버튼을 눌러 취소 상태 및 전송 버튼 복귀를 확인했다. 백엔드·모델 실행 로직은 이 UI 후속 변경에서 수정하지 않았다.

위 UI 확인 후 사용자 요청으로 진행 기록·완료 시간 글씨를 16px에서 14px로 줄였다. 회색 톤과 배치는 유지했다. `npx playwright test --config frontend/streaming.playwright.config.ts --grep 'inline work'`의 네 화면 폭 시나리오가 통과했으며, 실제 14px 적용과 가로 넘침이 없음을 확인했다. 이 글씨 크기 조정에서는 전체 모델·백엔드 검사를 반복하지 않았다.

최종 사용자 요청에 따라 사용자 질문과 AI 기본 본문은 15px, 회색 진행 기록·작성 상태·완료 시간은 14px로 확정했다. 같은 네 화면 폭 시나리오에서 스트리밍 중·완료 후의 실제 계산된 글씨 크기가 각각 요청한 값과 일치하고 가로 넘침이 없음을 확인했다(4개 통과). 이 CSS 조정에서도 모델·백엔드 검사는 반복하지 않았다.

## 운영 범위

입력창 하단 여백은 `--agent-composer-bottom-gap` 한 값으로 조절하게 했으며, 기본값을 16px에서 28px로 올렸다. 페이지 하단 여백과 sticky 위치에 같은 값을 적용했다. `npx playwright test --config frontend/streaming.playwright.config.ts`의 8개 시나리오가 통과했다(네 화면 폭, 자동 스크롤, 복원, 취소, 채팅방 분리).

이번 확인은 로컬 단일 앱·worker와 브라우저 기준이다. 외부 프록시의 SSE 버퍼링, 다중 인스턴스 부하와 장시간 대량 동시 접속은 검증하지 않았다. 연결 장애 시 동일 이벤트의 JSON 조회와 최종 상태 확인을 유지하며, 이 복구가 도구·모델 호출을 재실행하는 경로가 되지 않게 한다.
