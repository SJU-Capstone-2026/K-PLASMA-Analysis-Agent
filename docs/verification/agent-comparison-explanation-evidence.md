# 비교 설명 근거 오류·재시도 검증

2026-10-09, `feat/agent-comparison-charts`. 기준 구현은 `4a42343`, 적용 빌드는 `v1-2026-10-09.comparison-4`다. 단독 구현·검토이며 팀원 승인을 대체하지 않는다.

## 문제와 원인

RF 전류의 원본 특징값 계산과 그래프는 완료됐지만 설명 단계에서 `ANSWER_OBSERVATION_MISMATCH`가 발생했다. Phoenix에서 조회·계산과 설명 호출을 분리해 확인했다. 관측된 한 요청은 총 14.31초였고, 원본 출력 조회 56ms·계산 23ms에 비해 설명 호출과 실패 후 재호출에 각각 약 5.9초가 소요됐다.

압력·소스·바이어스 조건은 모델 입력의 Run에 있었지만 관찰 ID는 출력 지표·차이·요약에만 발급됐다. 모델이 여러 공정 조건이 함께 바뀌었다는 해석에 빈 근거 배열을 반환했고, 서버가 이를 거부했다. 제공자 스키마는 빈 배열을 허용해 런타임 검증과 불일치했다. 재시도에는 오류 코드만 전달됐고 실패한 답변은 전달되지 않았다.

## 수정

- 실제 선택 Run의 압력·소스·바이어스 조건에도 코드가 관찰 문장과 ID를 발급한다. 기존 출력 관찰 뒤에 추가해 그 ID를 유지하고 요청 지표·수치표·그래프 범위를 늘리지 않는다. 조건 자체가 요청 지표인 경우 중복 발급하지 않는다.
- 모델에 보내는 각 해석의 `observationIds`에는 `minItems: 1`과 해당 결과의 ID enum을 적용한다. 조건 해석도 관련 ID를 인용하며, 근거 없는 일반 주의 문장은 `limitations`로 구분한다. 런타임의 근거 검증을 완화하지 않는다.
- 설명은 기본적으로 핵심 해석 1–3개로 작성하고 표의 숫자·RF 위상 좌표를 반복하지 않도록 안내한다. 정량 결과는 코드가 만든 표와 관찰 문장에서 표시한다.
- 실패 후 한 번의 기존 재시도에 거부된 초안, 근거 없는 항목, 알 수 없는 ID, 숫자를 다시 쓴 문장 위치를 전달한다. 조회·계산은 반복하지 않는다. 그래도 실패하면 검증된 부분 결과를 보존하고 오류를 표시한다.
- 모델 근거의 80개 관찰·60,000자 예산 안에서 Run의 지표와 조건 근거를 함께 포함한다. 제외된 Run의 비교 문장을 노출하지 않으며 저장된 전체 선택·수치표는 보존한다.

## 계약·호환성

schema 2의 관찰 출처 metric enum에 세 공정 조건을 추가했다. 추가 조건은 알려진 Run의 `kind: run` 관찰에만 허용하며, 요청하지 않은 조건을 요약·차이 근거로 가장할 수 없다. Python·Java의 검증, API 스키마와 프론트 소비 테스트를 함께 갱신했다. schema 3은 기존 비교 필드 목록에 조건이 포함돼 있어 같은 출처 검증을 적용한다.

과거 저장 답변은 다시 생성하거나 덮어쓰지 않는다. 기존 schema 1/2/3 읽기와 출력 지표 목록은 유지한다. DB 마이그레이션은 없다. backend와 Python worker를 재시작한 뒤 새 질문으로 확인한다. 기존 미완료 요청은 build fence 정책에 따라 새 질문으로 제출한다. 설명 프롬프트는 `comparison-answer-3`, 근거 정책은 `observations-2`다.

## 실제 모델 검증

같은 RF 비교 요청의 계산 결과·도구 선택을 고정하고 수정 전과 최종 수정 후 설명 경로를 각각 5회 교차 실행했다. `gpt-5.6-luna`, 추론 `none`, 재시도 한 번 제한을 사용했다. 실제 API 호출의 경과 시간을 `time.perf_counter`로 측정했으며 지연을 인위적으로 추가하지 않았다. 원본·실험 수치·대화·원격 trace 본문은 Git에서 제외된 로컬 경로에만 보관한다.
