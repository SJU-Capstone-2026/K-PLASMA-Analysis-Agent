# LocalLLM v2.5.1: d1 선택지 순서 보존 수정

v2.5(`9dff87e`) 이후의 선택지 순서 수정 패치다.
같은 정상 5개·오류 5개에서 통과·반려와 지정 오류 항목 검출을 유지했고,
웹 서버 경로의 모델 입력·판정·점수를 예전 고정 실험과 일치시켰다.

웹 검토 서버가 선택지를 이름순으로 재정렬하면서 고정 실험과 다른 보기를 모델에 제시했다.
같은 정상 입력 두 개에 보기 순서만 바꾼 4회 대조에서, 웹 순서는 둘 다 `missing`,
실험 순서는 둘 다 `match`였으며 웹의 점수도 기존 웹 로그와 정확히 재현됐다.

## 변경

`runtimes/d1_mlx/service.py`의 `canonical_request()`에서 선택지 순서를 보존한다.
검사 ID 정렬, 입력 검증, 단일 처리, 지침·선택지 설명·발췌 방식은 유지한다.
Qwen 모델·생성 설정, 그래프와 최종 응답 계약은 변경하지 않았다.

기존 두 회귀 검사는 선택지 내용을 비교하는 데 더해 순서를 직접 비교하도록 강화했다.
예전 입력까지 재정렬해 비교하는 방식은 사용하지 않았다.

## 같은 정상 5개·오류 5개 재검증

같은 실제 과거 Qwen 정상 계획 5개와 실행 숫자 하나를 바꾼 오류 계획 5개를 사용했다.
원문·인용문·계획·지침은 고정하고, 웹과 같은 gateway·입력 검사·로컬 HTTP 서버를 거쳤다.
Q8+MLX 단일 처리, Docker 1536MiB와 실제 그래프 `plan_review_enabled=true`를 확인했다.

| 항목 | 예전 고정 실험 | 수정 후 서버 경로 |
|---|---:|---:|
| 정상 계획 통과 | 5/5 | 5/5 |
| 오류 계획 반려 및 지정 오류 항목 검출 | 5/5 | 5/5 |
| 정확한 오류 사유 | 4/5 | 4/5 |
| 세부 검사 정답 | 47/56 | 47/56 |
| 전체 세부 판정까지 일치한 계획 | 6/10 | 6/10 |

56개 검사 모두 예전 실험과 실제 모델 입력 토큰 배열·판정·선택지별 점수가 일치했다.
정상 반려율은 이 표본에서 0/5, 오류 항목 재현율은 5/5다.
부수적 오판 8개와 오류 사유 오판 1개는 남아 있다. 계획 단위 10/10을 세부 판정 전부의 정답으로 해석하지 않는다.

품질 평가 요청은 정확히 10회이고 내부 독립 검사는 56회다.
새 Qwen 계획·자동 재시도는 실행하지 않았다. 모두 최초 계획 검토 결과이며 재계획 평가가 아니다.
요청당 평균 검토 시간은 7.727초, 총 입력은 114,628토큰이다.
이 시간은 고정 계획의 gateway 요청 구간으로, 새 Qwen 계획이나 웹 질문 전체 응답 시간을 포함하지 않는다.

## 실행 준비와 보존

서버 코드 변경에 맞춰 전체 메모리 준비 7건을 새로 통과했다.
워커 프로토콜 준비는 최초 4요청과 평가 후 재연결 4요청, 총 8요청을 별도로 수행했다.
준비 7요청의 d1 부분은 내부 9개 인공 검사이며 워커 준비는 회당 Qwen 3/d1 1요청이다.
이 준비 호출을 품질 평가 10계획에 포함하지 않는다.

준비 메모리 피크 17.945GiB, 품질 평가 피크 18.160GiB, 경고·추가 스왑은 모두 0이다.
DB 원본 Run·버전·대화·요청의 집계와 해시가 전후 같다.
로컬 워커와 d1 서버만 새 코드로 재시작했고 기존 웹·백엔드와 다른 그래프 프로세스는 유지했다.
직접 HTTP 평가 중 대기 워커가 `LOCAL_RUNTIME_PROFILE_MISMATCH`로 종료돼 평가 후 재연결했다.
이후 같은 준비 증거·서버 파일·실행 프로필을 확인하고 워커 생존과 웹 연결을 재확인했다.
추가 정확도 평가는 하지 않았다. 동시 진단 중 상태 조회 실패로 워커가 종료되는 동작은 이번 선택지 수정에 포함하지 않는다.

`git diff --check`도 통과했다.

원시 입력·점수·메모리·로그와 실행기는 Git 제외 `.local/runtime/v2.5-d1-choice-order-fix/`에 비공개로 보관한다.
새 Qwen 계획을 생성하는 웹 앞 5문항 전체 흐름과 나머지 35문항은 이번 범위에서 재평가하지 않았다.
