# v2 조건별 Decisions 검토 검증

2026-11-06. 브랜치 `feat/v2-plan-semantics-review`. 최종 프롬프트 `plan-semantics-conditions-2`.

## 변경

기존의 포괄적인 세 질문 대신 계획의 필터 지표, 정렬, 비교 대상·출력·기준·경향 축, 계산, 선택 개수·출처, 조건부 실행을 각각 검사한다. 실제 단계에서 검사 위치를 만들며 원문을 표현별 코드 규칙으로 해석하지 않는다. 조건이나 확인 단계를 통째로 뺀 경우를 위한 범위 검사도 유지한다.

한 계획 검토는 Decisions HTTP 호출 한 번이다. 결과의 `choice`는 `match`, `unclear` 또는 항목에 허용된 `value_changed`, `unit_changed`, `boundary_changed`, `direction_changed`, `target_changed`, `missing`, `unexpected`다. 확률·confidence는 기록만 한다. 재계획 전체 최대 2회와 전체 모델 요청 13회 상한은 유지한다.

반려 시 코드가 원문 `sources`와 실제 계획 `plan_values`의 JSON pointer·값을 `checks[].issue`에 연결한다. 같은 증거가 `plan_review_feedback.issues`로 기존 재계획 모델에 전달되며 내부 모델 시도와 체크포인트에 저장된다. 증거를 모델이 새로 쓰게 하거나 새 일반 LLM으로 이유 문장을 생성하지 않는다. `reason:null`은 자유형 반려 설명이 없다는 내부 기본값이며, 이 조건별 증거와 구분한다.

schema 2는 현재 검사 집합 전체를 확인한다. 일부 항목만 응답하거나 모르는 이름·유형을 반환한 경우, 응답이 누락·중복되거나 과거 schema 1 PASS인 경우 새 실행 승인이 될 수 없다. 과거 기록 읽기는 유지한다. 정상적으로 계획한 HITL 선택은 승인된 계획을 재사용한다.

## 최종 고정 평가

기존 인공 계획 13쌍을 바꾸지 않고 각 3회, 총 78회 실제 Decisions로 검토했다. 정상·오류 정답은 사람이 작성한 기준이며 Decisions가 정답을 만들지 않는다. 표는 **고정 계획의 통과·반려 정확도**다. 전체 에이전트 수행률이나 반려 이유 하나하나의 정확도는 아니다.

| 지표 | 이전 v9 | 최종 조건별 v2 |
|---|---:|---:|
| 정상 계획 통과 | 30/39 | 39/39 |
| 정상 계획 오탐 | 9/39 | 0/39 |
| 오류 계획 차단 | 39/39 | 39/39 |
| 오류 계획 통과 | 0/39 | 0/39 |
| API 장애·판정 불가 | 0 | 0 |

기존 오탐 P01(중첩 비교·범위 검색), P11(직접 기준 선택), P13(후보 정렬·정확히 두 개 선택·직접 기준 선택)은 모두 정상 3/3 통과·오류 3/3 반려했다. 그 밖에 IEAD 비교, 빈 결과와 범위/equality 구분, 필터 누락, 이상/초과 경계, Torr 배율, max/mean, 후보 전체/기존 선택 대상, 확인 생략, 정렬 반전, 독립 검색 그룹을 포함했다.

검토 평균 시간은 약 0.368초였다. 평균 입력은 이전 약 4,914토큰에서 약 6,899토큰으로 약 40% 증가했다. 한 호출의 검사 항목은 평균 약 7.73개다. 호출 수는 늘지 않지만 조건별 질문 때문에 입력 비용은 증가한다. 네트워크·캐시·실행 시점이 다르므로 시간 차이를 검토 방식만의 인과 효과로 해석하지 않는다.

최종 평가와 보완 단계는 구분한다. 먼저 오탐 3종의 6회 확인과 초기 78회를 수행했고, 코드 검토에서 경향 축·실행 조건 검사를 보완한 뒤 78회에서는 P13 정상 3건이 다시 반려됐다. 원인은 기준 선택을 비교 단계와 확인 단계에서 중복 검사하는 항목이었다. 코드가 연결을 검사하는 기준 확인은 비교의 전용 항목 하나가 의미 검토를 담당하도록 정리했다. 그 뒤 수행한 최종 78회가 위 결과다. 보완용 162회는 최종 표본에 합치지 않는다.

## 반려 이유의 한계

항목별 이유 역시 모델 판정이다. 최종 평가의 오류 계획 P04는 실제로 빠진 압력 조건을 포착하면서, 그대로 있는 ionFlux 조건도 추가로 `missing`이라고 지목했다. 이 추가 오지목은 원본 기록에 그대로 남겼다. 따라서 **정상/오류 판정 78/78이 모든 반려 사유까지 맞았다는 뜻은 아니다.** 원문과 실제 값을 코드가 붙이는 이유도 모델의 지적을 사람이 대조할 수 있게 하기 위함이다. 작은 고정 표본의 결과를 임의의 질문에 일반화하지 않는다.

제품 기본 `AGENT_V2_PLAN_REVIEW_ENABLED=false`는 유지한다. 실제 로컬 웹 검증용 워커에서는 명시적으로 `true`를 적용해 새 요청을 시험할 수 있게 재실행했다. 실제 `.env`는 변경하지 않았다.
