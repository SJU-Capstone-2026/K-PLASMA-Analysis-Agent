# LocalLLM v2.6.1 Qwen 계획 인용 복원

## 핵심 결과

Qwen이 계획 근거를 인용할 때 생긴 공백 차이를 코드가 원문으로 복원한다. v2.5.2의 저장된 Q01·Q05 최초 계획에서 인용 **4곳·2곳**을 복원했고, 두 계획 모두 d1 전 단계인 계획 검증을 통과했다.

캐시가 적중한 최신 웹 평가에서는 Q01·Q05의 **최초 통과 0/2 → 2/2**, 재계획 **2회 → 0회**, 평균 워커 실행 **62.428초 → 42.642초(31.7% 감소)**를 관측했다. 같은 문항의 [v2.5.2 캐시 ON 평가](2026-11-18-local-llm-cache-on-web5.md)와 비교했다. 이번 두 새 계획의 인용은 생성 시점부터 원문과 일치했다.

## 공백 복원 범위

v2.5.2의 Q01·Q05에서는 Qwen이 `Run의`처럼 붙어 있는 표현을 띄어 써서, 실제 조건과 값이 올바른 최초 계획이 원문 인용 검사에서 반려됐다. 두 질문 모두 계획을 한 번 더 생성한 뒤 d1에 도달했다.

`core/plan_validation.py`에서 요구사항 `requirements[].sources[]`와 실행 입력 `LiteralInput.source`의 인용을 같은 규칙으로 처리한다.

1. `message_key`가 가리키는 질문 또는 입력 이력에서 정확한 원문 구절을 먼저 찾는다.
2. 정확한 구절이 없으면 토큰 사이 ASCII 공백의 개수 차이와 `Run` 뒤 지정한 한국어 조사 앞 공백을 비교한다. 예를 들어 `300  W`와 `Run   을`을 대응하는 원문에서 찾는다. 원문에 공백이 있었던 토큰 경계는 보존한다.
3. 대응하는 연속 구절이 한 곳이면 계획 사본의 `quote`에 실제 원문을 넣는다. 숫자 일부, 부호·단위·문자 차이, 개행 차이, 여러 후보는 기존 `INVALID_PLAN` 경로로 처리한다.
4. 승인 가능한 계획은 기존 d1 의미 검토로 넘긴다. 이 과정에서 모델 원본 초안과 이전 저장 기록을 보존한다. 정규화 대상은 `quote`이며 실행 입력값·단위·단계와 `message_key`는 원래 계획을 따른다.

릴리스 이름은 v2.6.1이며 실제 웹 요청의 그래프 이름은 `v2_localLLM`이다. 기존 `submit_plan` 계약, 검토 단계, 최종 응답 계약을 사용한다.

## Q01·Q05 웹 비교

기존 40문항 중 두 문항을 순서대로 별도 새 대화에서 한 번씩 제출했다. 새 초기 계획 생성과 d1 검토를 실행 기록에서 확인했다. 이전에 저장한 동일 문항과 동일한 자동 채점 기준을 사용했다.

| 문항 | v2.5.2 캐시 ON 판정 | v2.6.1 판정 | 대기 이전 → 현재 | 실행 이전 → 현재 | 전체 이전 → 현재 |
|---|---|---|---:|---:|---:|
| Q01 | 재계획 1회 후 최종 통과 | 최초 d1 PASS·최종 통과 | 0.089 → 1.120초 | 63.064 → 37.762초 | 63.153 → 38.882초 |
| Q05 | 재계획 1회 후 최종 통과 | 최초 d1 PASS·최종 통과 | 0.017 → 1.038초 | 61.791 → 47.521초 | 61.808 → 48.559초 |

전체는 접수부터 실행 종료까지다. 실행은 DB의 워커 실행 시간이며, 대기는 전체에서 실행을 뺀 값이다. 전체 응답은 Q01 **24.270초**, Q05 **13.249초** 줄었다. 두 평가 모두 문항마다 최초 계획이 디스크에서 **10,491토큰**을 재사용했다. d1은 문항마다 한 번 실행됐고 현재 평가의 재계획과 답변 재작성은 각각 0회다.

| 문항 | 이전 Qwen 최초 / 재계획 | 이번 Qwen 최초 | 빠진 호출 |
|---|---:|---:|---:|
| Q01 | 21.458초 / 26.728초 | 23.675초 | 재계획 1회 |
| Q05 | 19.692초 / 28.848초 | 35.898초 | 재계획 1회 |

Qwen 시간은 엔진의 입력 처리와 생성 시간 합계다. 캐시가 양쪽에서 적중한 조건에서 재계획 호출이 빠진 효과가 관측됐다. Q05는 이번 첫 계획 생성 자체가 더 길어 전체 단축 폭이 작았다.

### 첫 코드 적용 직후의 측정

별도 웹 실행에서도 최초·최종 통과는 각각 2/2였다. Q01은 구현 식별자가 바뀌어 이전 캐시를 읽지 못했고 **87.566초**에 끝났다. Q05는 캐시가 적중했지만 Q01 직후 메모리 보호로 워커가 종료돼 기존 요청이 **174.466초** 대기했다. 동일 설정으로 워커를 다시 시작한 뒤 실행 **44.205초**, 전체 **218.671초**로 완료했다. 위 표는 두 문항 모두 캐시가 적중하고 같은 워커에서 완료한 후속 실행을 사용한다.

| 계획과 복구 | 실행 전 모델 설정·그래프와 실행 중 체크포인트의 `plan_review_enabled=true` 확인, 재계획 최대 2회·필요한 답변 재작성 최대 1회 |

| 데이터 | 기존 Run과 Run 버전 각 150개 해시 보존, 웹 요청·대화 턴 각 2건 추가 |

회귀 검사는 지정 메시지의 원문 구절 복원, 숫자·단위 변경과 모호한 인용의 반려, 복원 인용이 실제 그래프의 d1 검토에 전달되는 경로를 검사한다. 이전 Q01·Q05 계획의 복원은 저장 초안으로 재검증했다. 이번 웹 계획의 정확한 인용과 복원 동작의 증거를 각각 기록했다.

```sh
cd agent/python
.venv/bin/python -m pytest -q -c pytest-v2-local-llm.ini
```

로컬 그래프 테스트 806개 통과·8개 제외. 테스트에는 독립 복제 경계 검사가 포함된다. 웹 수치는 Q01·Q05 각각 1회 기준이다. 원시 질문·계획·응답과 계측은 Git에서 제외한 `.local/runtime/v2.6-citation-web2/`와 `.local/runtime/v2.6-citation-warm-web2/`에 보관한다.
