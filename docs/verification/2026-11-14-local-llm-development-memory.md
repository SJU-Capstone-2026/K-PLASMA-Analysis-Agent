# Docker 2GiB와 경고 허용 개발 평가

## 적용 범위

사용자 지시로 Docker Desktop VM 설정을 2048MiB로 줄이고 로컬 개발 프로필에
`AGENT_V2_LOCAL_LLM_MEMORY_POLICY=development`를 명시했다.
기본 `strict`는 유지한다. 개발 정책에서는 macOS 압력1·2를 허용하며 swap 변화를 기록한다.
심각 압력4는 준비 검사와 다음 모델 단계 진입에서 차단한다.
모델 오류·토큰/시간/재계획 예산·계약 검사는 그대로다.

Qwen9B Q4_K_M, context24576, batch/ubatch256, 생각2048, 출력6000, 호출90초와
d1 Q8_0 계획 검토ON을 유지했다. 그래프·최종 응답 필드는 바꾸지 않았다.
이 결과를 strict 정책의 안정성 통과로 해석하지 않는다.

## Docker와 데이터

- DB 정상 정지 후 Desktop을 재시작해 `MemoryMiB=2048`을 적용했다.
- 엔진이 보고한 가용 메모리는 2,066,317,312바이트(약1.924GiB)다.
- 동일 DB 컨테이너·volume과150 Run·150 version을 유지했다.
- 재시작 후 DB cgroup OOM·OOM kill은0이다.
- 기존5173 웹·8080 백엔드·DB를 사용한다. 만료된8시간 브라우저 인증은 같은 백엔드 설정으로 갱신했다.

## 실제 메모리 검사

검사는 실제 Qwen·d1과 임시 인공 DB·웹·브라우저를 함께 실행한다.
원시 증거는 Git 제외 `.local/runtime/v2.2-memory-policy/`와 임시 폴더에 보관한다.
측정 전후 실행 인스턴스와 프로필이 일치하는 원본 보고서만 준비 증거로 쓴다.

| 항목 |캐시 OFF|캐시 ON|
|---|---:|---:|
| 고정 인공 입력/계획 검사 |7/7|7/7|
| 압력 표본 |94|297|
| 정상 / 경고 / 심각 |92 /2 /0|297 /0 /0|
| 측정 resident 피크 |19.542GiB|19.382GiB|
| swap 시작 / 끝 / 피크 |3153.25 /3153.25 /3153.25MiB|3146.50 /3146.50 /3146.50MiB|
| 실제 캐시 저장·sleep·복원·d1 왕복 |해당 없음|통과·d1 PASS2회|

resident는 기존 측정기의 active+wired+physical compressor 합이며 Mac 전체 사용량과 같지 않다.
캐시 OFF에서는 경고2개를 기록하면서7개 검사를 끝냈고 swap 증가는 없었다.

프로젝트 루트에서 실행:

```sh
JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home \
node -- scripts/agent/measure-local-llm.mjs \
  --env-file .local/runtime/v2.2-memory-policy/cache-off.env
```

## 현재 공용 실행 설정과 남은 확인

평가용 ON 서버는 종료하고 원래 Qwen 실행 인자를 복원했다. 공용 로컬 워커에는 새로 통과한
OFF 메모리 증거와 `MEMORY_POLICY=development`를 적용했다. Docker2048MiB와 d1 검토ON을 유지한다.
캐시 기본값은 계획서대로OFF다. 캐시 운영 전환·commit/push는 수행하지 않았다.
공용 로컬 워커의 실제 `worker ready: graph=v2_localLLM` 로그와 프로세스 생존을 확인했다.
Chrome용 새 접속 파일을 열었으나 마지막 일반 Chrome 화면 확인은 도구 미연결로 수행하지 못했다.
이 제한은 앞선 headless 웹10회 자동 UI 검사와 별도로 기록한다.

실제 재계획은10문항 모두 발생하지 않아 디스크/RAM 재계획 경로의 실모델 성적은 이번 평가에 없다.
해당 오류·복구 분기는 소프트웨어 회귀로 검사했다. Q03 추가 답변 검토와40문항 전체 성능 검증은 남아 있다.

커밋·push는 수행하지 않았다. 원시 응답·Run 수치·캐시·세션/인증값은 이 문서에 포함하지 않는다.
