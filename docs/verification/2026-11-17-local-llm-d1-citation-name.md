# d1 인용 출처 이름 변경 — source.quote → citation.quote

2026-11-17, Asia/Seoul.

**핵심:** 같은 숫자 발췌 입력에서 인용 출처 이름을 citation으로 바꾸자 정상 계획 통과는 **2/5→3/5**, 전체 검사 정답은 **43/56→45/56**으로 개선됐다. 실제 오류 항목·사유 검출은 **5/5 유지**다. 소스 전력의 부수 오판은 **5개→3개**로 줄었으나, 독립된 정상 소스 사례 3개 중 복구된 것은 R01 한 개다. R02의 unexpected와 R03의 missing은 남았다. **토큰 수는 완전히 같고**, 평균 모델 score는 관측상 **6.824→6.926초**였다. 평가 중 메모리 warning 14표본·추가 swap 약448MiB가 있었으므로 작은 시간 차이를 이름 변경의 성능 비용으로 해석하지 않는다. 공용 제품 입력 정책은 변경하지 않았다.

## 기준과 평가 결과

기준은 [직전 숫자 필드 발췌 평가](2026-11-17-local-llm-d1-numeric-excerpt.md)의 저장된 결과다. 기존 2번+조건부 1·4·5번 지침과 같은 실제 Qwen 정상 5개·오류 5개를 사용했다. 정상 인용을 보존하고 실행 숫자 하나만 바꾼 사본이다. 기준을 다시 호출하지 않았으며 새 후보의 10개 계획·56개 검사를 한 번씩 실행했다.

## 바꾼 것과 보존한 것

평가용 어댑터 `agent/python/evals/local_llm_d1_citation_view.py`, 버전 numeric-citation-name-1을 사용했다.

- 숫자 발췌 요청 22개에 포함된 리터럴 인용 객체 24개에서 source 키를 citation으로 바꿨다. 범위 양쪽 경계의 인용도 각각 이름만 변경했다.
- 공통 지침과 `tool_contracts.bindings.literal` 안의 고정 경로 표기를 source.quote→citation.quote로 맞췄다. 거절 조건·예외·검사 범위의 의미는 바꾸지 않았다.
- source_power·sourcePower 등 실제 소스 전력 이름은 유지했다. 숫자·단위·인용문·사용자 원문·이력·검사 위치·선택지 ID/설명/순서·확률 보정값을 유지했다.
- 사용자 질문이나 인용문 안의 글자는 치환하지 않았다. 발췌 범위 표시·계획 구조·생략 범위·나머지 도구 설명·정책도 유지했다.
- 누락·정렬 34개는 native 요청과 실제 패킹을 바이트/토큰 수준으로 보존했다. 어댑터를 다시 적용한 56개 입력이 frozen 후보와 같음을 CPU에서 확인했다.
- 실제 실행 계획·DB의 원본 계획·전체 검토 context·그래프·도구·최종 JSON/SSE와 저장 계약은 변경하지 않았다. 결과는 기존 normalize_response/parse_plan_review가 원본 context로 그대로 재현했다.

이번 비교는 자료 키와 그 고정 경로 참조를 함께 바꾼 하나의 이름 변경이다. 데이터 키만 바꾼 효과와 지침·도구 설명의 경로 이름을 바꾼 효과를 각각 분리한 실험은 아니다.
