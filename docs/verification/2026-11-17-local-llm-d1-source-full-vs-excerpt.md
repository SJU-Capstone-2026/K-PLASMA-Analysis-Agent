# LocalLLM v2.5 — 소스 전력 검사 전체 입력·발췌 입력 4회 비교

## 핵심 결과

정상 R02·R03의 소스 전력 검사에서 전체 입력은 둘 다 `match`, 발췌 입력은 각각 `unexpected`·`missing`이었다. 지시서·선택지·현재 검사 대상의 `citation.quote`·실행값·단위·도구 설명을 고정해도 입력 구성에 따라 정상 판정이 무너지는 현상을 재현했다.

이는 이 두 사례에서 전체 입력과 발췌 입력 사이의 차이가 오판을 유발한다는 증거다. 이번 비교는 발췌 과정에서 함께 변하는 계획·검사 목록·실행 요약·발췌 표시를 하나의 구성으로 비교했으므로, 그중 어느 부분이 원인인지는 아직 분리하지 않았다.

## 범위와 유지 조건

- 실제 Qwen 정상 계획 R02·R03의 `filter.s_forward.source_power`만 각 구성에서 한 번씩, 총 4회 추론했다. 다른 검사·오류 계획·Qwen 재계획·최종 답변·웹 전체 평가는 실행하지 않았다.
- d1: LiquidAI/d1-2B, revision `a6bce774e6dde338dcc3036ceb5d91f78bf4c19e`, MLX Q8 affine8/group64. 기존 BF16 임베딩·정규화·비양자화 계층 구성은 유지했다.
- MLX 0.32.4 / mlx-decision 1.3.0, GPU Metal, 그룹 크기 1·독립 배치 크기 1. 한 모델 인스턴스에서 네 요청을 순서대로 독립 채점했다.
- Docker VM 1536 MiB(1.5 GiB), 개발 메모리 정책 유지. 시작 전 설정과 실제 그래프 상태에서 `plan_review_enabled=true`를 확인했다.
- 공통 지침은 앞선 실험의 기존 2번+조건부 1·4·5번 구성이다. 범위를 좁혔다가 거절된 수정 2번 지침은 사용하지 않았다.
- 추가 예열·추론 재시도·숨은 준비 호출은 0회다. 토큰 배치 검사는 모델 추론 없이 수행했다.
- 운영 코드·그래프·응답 직렬화·공유 웹/백엔드/DB·작업자 설정은 변경하지 않았다. 실험 구성의 운영 반영도 하지 않았다.

## 입력 대조

각 사례의 두 요청에서 다음이 동일함을 사전 검증했다.

- 전체 `questions` 객체: 지시서, 선택지 순서와 설명, 검사 경로.
- 원본 질문·이력·확정 문맥·정책·도구 설명·완료 단계·리비전·프롬프트 버전.
- 소스 전력 리터럴의 값·단위·인용문·메시지 키.
- 엔진에 실제 배치되는 선택지 토큰 ID와 온도. 입력 잘림은 네 요청 모두 없었다.

전체 구성은 기존 전체 입력에 `citation` 표기를 일관되게 적용했다. 실제 계획 안의 세 리터럴뿐 아니라 실행 요약 문자열 안의 같은 인용 객체도 동일하게 이름을 바꿨으며 인용문 본문은 유지했다. 발췌 구성은 직전 citation 실험의 요청을 그대로 재사용했다.

서로 다른 상태 구역은 `plan`, `check_specs`, `program_effects`, `review_view` 네 곳이다. 전체 구성은 다른 입력값·요구사항 설명·검사 목록·실행 요약을 포함하고, 발췌 구성은 해당 수치 부분과 발췌 표시만 남긴다. 따라서 이번 결과를 ‘다른 실행값 하나를 지워서 생긴 문제’ 또는 ‘긴 인용문 하나 때문’으로 단정하지 않는다.

## 선택지별 점수

정규화된 모델 선택 점수이며 정확도나 실제 정답 확률을 뜻하지 않는다. 가장 높은 점수를 최종 선택지로 사용한다.

| 선택지 | R02 전체 | R02 발췌 | R03 전체 | R03 발췌 |
|---|---:|---:|---:|---:|
| match | **89.35%** | 16.23% | **83.21%** | 23.41% |
| value_changed | 0.63% | 0.30% | 1.17% | 0.35% |
| unit_changed | 0.81% | 0.45% | 1.37% | 0.45% |
| boundary_changed | 0.43% | 0.17% | 0.55% | 0.23% |
| missing | 2.24% | 30.73% | 4.20% | **46.16%** |
| unexpected | 1.23% | **46.86%** | 1.66% | 25.42% |
| unclear | 5.31% | 5.26% | 7.85% | 3.98% |

R02의 match 점수는 발췌 후 73.12%p, R03은 59.80%p 낮아졌다. 발췌 두 요청은 직전 실험과 일곱 선택지의 원래 부동소수점 점수까지 정확히 일치했다.

## 해석과 한계

동일한 Q8 모델·엔진이 전체 입력에서는 두 정상 조건을 맞혔다. 따라서 해당 값 자체를 비교할 능력이 전혀 없거나 citation 이름만으로 항상 오판한다고 설명할 수 없다. 정상 값·인용문이 유지되는데도 발췌 구성에서 오판한다는 점이 이번에 확인된 사실이다.

제거된 정보 중 무엇이 판정을 지지했는지, 또는 발췌 표시가 누락으로 해석됐는지는 후속 분리 실험이 필요하다. d1은 선택지 점수를 반환하므로 내부 판단 이유를 모델이 직접 설명했다고 해석하지 않는다. 정상 두 건만 비교했으므로 오류 검출 정확도와 전체 그래프 성능에 대한 결론도 내리지 않는다.

## 환경·무변경 검증

- 메모리 표본 14개, 경고 0개, critical/unknown 0개, 추가 swap 0 bytes.
- 운영체제 메모리 사용 피크 18.31 GiB, MLX 할당 피크 2.72 GiB. 서로 다른 측정 범위이며 더하지 않는다.

## 실행 근거와 로컬 보관
