# LocalLLM v2.5 — 발췌 + citation.quote 3회 반복 평가

## 핵심

기존 발췌 + `citation.quote` 입력을 그대로 정상 5개·오류 5개씩 3회 반복했다. **세 회차 모두 정상 통과 3/5, 오류 항목·사유 검출 5/5, 개별 검사 정답 45/56**이었다. 기존 평가와 비교해 168개 검사의 선택뿐 아니라 일곱 선택지의 원래 점수까지 정확히 같았다.

계획당 모델 채점 시간은 세 회차 평균 **6.904초**, 기존 **6.926초**였다. 입력 토큰은 완전히 같고 시간 차이는 약 −0.31%에 그쳤다. 입력·코드가 동일한 반복이므로 성능 개선으로 해석하지 않는다. 오류 숫자를 모두 검출하는 특성과 정상 소스 전력을 오판하는 문제가 함께 재현됐다.

## 범위와 조건

- 사용자 확인에 따라 전체 계획 구성은 새로 평가하지 않고, **기존 발췌 구성만** 반복했다.
- 실제 Qwen 정상 계획 5개 및 인용문을 유지하고 실행 숫자 하나만 바꾼 오류 사본 5개를 사용했다. 같은 10개를 3회 실행한 것으로, 서로 다른 질문 30개가 아니다.
- 한 회차는 숫자 검사 22개와 기존 누락·정렬 검사 34개, 총 56개다. 숫자 검사만 해당 인자·인용문을 발췌하고 `citation.quote`를 사용한다. 누락·정렬 요청은 기존 구성 그대로 유지했다.
- 새 d1 채점은 **30개 계획·168회**다. 새 Qwen 호출·모델 예열·자동 재시도·Run 도구 실행·REPLAN·답변 재작성·추가 웹/API 문항은 0회다. 고정된 계획의 첫 d1 검토를 비교했다.
- Q8+MLX, group_size=1·independent_batch_size=1, Metal GPU를 유지했다. 이전 실행과 같이 계획마다 모델을 적재하고, 해당 계획의 검사 5~6개를 독립적으로 하나씩 채점한 뒤 해제했다.
- Docker VM 1536 MiB(1.5 GiB), development 메모리 정책, d1 검토 활성화를 유지했다. 실행 전 설정과 실제 그래프 상태의 `plan_review_enabled=true`를 확인했다.
- 지시서·선택지·원본 질문·인용문·실행값·도구 설명을 변경하지 않았다. 기존 2번+조건부 1·4·5번 지침을 그대로 사용했다.
- 운영 코드·그래프·최종 JSON/SSE·저장 계약·공유 웹/백엔드/DB·작업자 설정은 변경하지 않았다.

## 판정 재현성

모든 입력 파일은 기존 평가 파일과 바이트 단위로 같았다. 실제 tokenizer 배치도 각 요청의 전체 token ID·선택지 token 그룹·온도·요청 hash까지 같았다. 세 회차의 기존 대비 선택 변경은 0개, 최대 선택지 점수 차이는 **0.0**이었다.

| 사례 | 정상 계획 판정 — 매회 동일 | 바꾼 숫자 종류 | 오류 계획의 목표 검사 — 매회 동일 |
|---|---|---|---|
| R01 | PASS | 압력 | value_changed |
| R02 | ISSUE — 정상 소스 전력 unexpected | 소스 전력 | value_changed |
| R03 | ISSUE — 정상 소스 전력 missing | 바이어스 전력 | value_changed |
| R04 | PASS | 에너지 범위 상한 | value_changed |
| R05 | PASS | 플럭스 하한 비교값 | value_changed |

기존 작업·필터 누락·정렬의 부수 오판과 소스 전력 오판도 그대로였다. 이번 반복은 같은 입력에 대한 재현성을 보여주며, 원인을 분리하거나 새로운 질문에 대한 일반 정확도를 검증한 실험은 아니다. d1 선택 점수는 내부 판단 이유를 설명하는 문장이 아니므로 모델이 어떤 생각을 했다고 단정하지 않는다.

## 시간 해석

모델 채점 합계는 207.128초, 계획당 평균 6.904초, 검사당 평균 1.2329초였다. 기존 대비 계획당 차이는 약 −0.022초(−0.31%)다. 회차 평균의 범위는 6.868~6.967초이며 표본 표준편차는 0.0544초다.

채점 시간은 `backend.score` 시작부터 GPU 동기화 완료까지다. 가중치 로드·프로세스 시작·별도 토큰 패킹·실행기 폴링·웹 처리는 제외했다. 계획 처리 wall 평균은 각 회차 7.796초·7.900초·7.993초였으며, 이 수치도 Qwen 계획 작성이나 최종 답변을 포함하는 웹 전체 응답 시간은 아니다.

기준은 이전 1회 기록이고 새 반복은 3회다. 메모리 압력과 OS 실행 상태가 달랐으므로 작은 시간 차이를 최적화 효과나 모델 성능 변화로 해석하지 않는다. 이번에는 입력·지시서·모델 자체의 변경이 없었다.

## 검증과 비공개 산출물

입력 준비 assert와 168회 호출 한도 검증을 먼저 수행했다. 각 회차의 실제 tokenizer 사전 검사는 가중치 적재·추론 없이 끝났으며, 실제 추론 시에도 요청별 패킹을 다시 대조했다. 각 회차의 56개 원시 결과를 기존 `normalize_response`와 `parse_plan_review`로 읽어 선택·확률·최종 검토 상태가 일치함을 확인했다.

기존 산출물을 덮어쓰지 않았다. 각 회차는 Git 제외 `.local/runtime/v2.5-d1-citation-repeat3-r1/`, `-r2/`, `-r3/`에, 전체 계획·집계는 `.local/runtime/v2.5-d1-citation-repeat3/`에 보관한다. 원시 질문·실제 계획·인용·토큰·점수는 로컬에만 남겼고 폴더 700·JSON 600 권한을 확인했다.

실행 명령은 다음과 같다. 반복 보호가 있으므로 같은 산출물 경로에서 자동으로 다시 실행하지 않는다.

```text
agent/python/.venv/bin/python .local/runtime/v2.5-d1-citation-repeat3/run.py
agent/python/.venv/bin/python .local/runtime/v2.5-d1-citation-repeat3/aggregate.py
```

세 회차 모두 환경·파서 검증을 통과했으며 총 168회 추론이 완료됐다. 공용 제품 코드 수정·입력 정책 반영·추가 모델 실험·웹 평가·Git 커밋·push·PR·배포는 하지 않았다.
