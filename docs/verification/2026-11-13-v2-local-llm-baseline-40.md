# v2_localLLM 현재 설정: 실제 웹 40문항 평가

2026-11-13, 복원한 150개 Run을 대상으로 동결 40문항을 실제 브라우저에서 한 번씩 실행했다.
자동 정답 검사 결과는 **5/40 (12.5%)**다. 재계획 없이 통과한 문항은 2개,
재계획 후 통과한 문항은 3개, 실패는 35개다. 사용자 요청에 따라 **API 평가는 0회**로 종료했다.

## 실패가 발생한 위치

질문 처리에 기록된 모델 시도는 123회다. 계획 생성 40회·재계획 72회·계획 검토 7회·
답변 작성 3회·답변 검토 1회다. 이 수는 시작 전 인공 준비 검사와 별개다.

계획 응답 112회 중 **96회가 인자 구조 검사에서 실패**했다. 그 96회 모두 실제 native
`submit_plan` 호출 1개를 포함했다. 63회는 문자열로 전달된 `steps`/`requirements` 내부 JSON이
깨져 있었고, 33회는 필드 누락·허용되지 않는 필드·형식 등의 오류였다. 올바르게 직렬화된
문자열을 제한적으로 해석하는 기존 호환 처리 뒤에도 실패한 결과다.

형식을 통과한 계획에도 실행 전 오류가 있었다. 원문에 없는 인용이나, 아직 실행하지 않은
검색 단계가 자기 자신의 출력을 입력으로 참조하는 계획이 확인됐다. 복합 비교·선택 문항은
의미 검토나 실제 사용자 선택까지 도달하지 못한 경우가 많았다. 사용자 입력 이벤트는 0개다.

추가 조사에서 형식 검사에 통과한 16개 계획을 기록된 attempt key 순서와 실제 저장된
revision에 대조해 원래 validator로 재검증했다. **7개는 실제 수용된 계획과 정확히 일치했고,
9개는 실행 전 검증에 실패**했다. 9개는 자기 출력 참조 7개, 원문과 다른 인용 1개,
설명 단계의 개수·배치 규칙 위반 1개다. 모델 재호출 없이 저장 기록으로 확인한 결과다.

96개 형식 오류의 관측 지점은 LM Studio가 돌려준 native tool arguments다. Qwen의 파서 적용 전
원시 생성문과 API 변환 결과를 함께 기록한 실험이 아니므로, 모델 생성과 MLX/LM Studio의
도구 인자 변환이 각각 얼마나 기여했는지는 확정하지 않는다. native 도구 연결 자체의 실패나
최종 사용자 응답 필드 파손으로 분류하지 않는다.

계획 revision이 저장되고 d1 검토에 도달한 경우는 7회이며 모두 PASS였다. 이 결과로
Decisions의 독립 정확도를 추정하지 않는다. 계획 검토 PASS는 최종 답변의 정답을 대신하지 않는다.
추가 조사에서는 **Q04의 잘못된 계획을 d1이 통과시킨 사례**를 확인했다. 요청에 없는 pressure
조건이 추가됐고, 실제로 불필요한 pressure 입력을 요구하며 진행이 막혔다. 해당 조건의 d1
선택 점수도 match와 missing이 매우 가까웠지만, 현재 판정 코드는 confidence에 의한 보류 없이
choice가 match이면 통과한다. 이 정책은 기존 v2에서 유지한 것이며 d1에 대한 보정 실험은 하지 않았다.
한편 순수 개념 답변은 기존 그래프에서 작성 후 바로 종료하므로 I01/I02의 본문은 d1 답변 검토를
받지 않았다. 이 두 본문 오류를 d1이 읽고도 승인한 사례로 세지 않는다.
서버 요청 상태는 COMPLETED 39개·CANCELLED 1개였지만, 완료 상태와 정답 검사 통과는 별개다.
취소 1개는 정해진 행동에 없는 추가 텍스트 입력을 요구해, 임의 답변 없이 종료한 문항이다.

## 자동 통과와 응답 품질의 차이

자동 점수는 동결된 조건·대상 Run·수치·단위·선택 절차·일부 텍스트 조건을 검사한다.
불필요한 추가 설명을 모두 금지하거나 모든 과학적 문장을 검증하지는 않는다.
평가 도중 이 기준은 바꾸지 않았다.

- **B05, 13번째 문항:** 조회 결과는 맞았지만 요청하지 않은 `explain_answer`를 추가했다.
  결과와 단위 환산을 반복했고 `mTorr mTorr`, `W W`처럼 단위를 중복 표기했다.
  자동 정답 검사 통과와 별개로 응답 품질 개선이 필요하다.
  원래 지시서는 해당 조건 조회에 `forward_lookup`을 쓰고, 조회만 요청하면 설명 단계와
  interpretations를 추가하지 말라고 명시하지만 실제 계획은 `reverse_search`와 설명 단계를 썼다.
  단위 중복은 모델이 단위까지 포함되는 값 참조 뒤에 단위를 다시 붙여 발생했다. 현재 참조 검증과
  근거 범위 검토는 이 중복이나 불필요한 설명을 차단하지 못했다.
- **I02, 36번째 문항:** 자동 검사는 통과했지만 IED 폭과 예시 구간의 너비가 서로 맞지 않는다.
  폭의 정의 없이 대부분의 이온이 특정 구간에 들어간다고 단정하고, 평균 이온 에너지와
  총 전달 에너지도 혼동한다. 별도 내용 검토에서는 실패로 기록했다.
- **I01:** 자동 검사도 실패했다. 플라즈마 문맥에서 요구한 입자 플럭스 기본 관계 대신
  생물학적 막의 이동 설명으로 벗어났다.

위 검토는 자동 평가기와 별도로 응답·산술 일관성을 확인한 소프트웨어 내용 검토이며,
과학 전문가의 검토를 수행한 것으로 표시하지 않는다. 자동 12.5%를 최종 과학적 정확도로 보고하지 않는다.

예상하지 않은 입력 요구 1개, 질문 표시·대화 복원 검사 2개다. I02/I03의 질문 표시·복원

## 실행·보존과 검증 근거

기존 실행기는 웹 40회 뒤 API 40회를 시작하는 구조다. 실행 도중 사용자가 웹 평가까지만
요청해, 마지막 웹 접수 후 상위 실행기만 일시 정지했다. worker와 브라우저는 실제 마지막
문항을 마쳤고, 원래 grader·DB export·복구 집계로 해당 결과를 저장한 뒤 실행기를 인터럽트했다.
상위 명령의 종료 코드 1은 이 의도적인 범위 변경에 따른 것이며 성공 종료로 보고하지 않는다.
별도 종료 제어기는 코드 0으로 끝났고, 40개 고유 웹 요청·40개 문항·API 접수 0개를 검증했다.
마지막 결과를 재접수하거나 추정으로 채우지 않았다.

원시 문항·정답·답변·모델 인자·브라우저 trace·160개 폭별 캡처·DB 스냅샷은 Git 밖의 비공개
디렉터리에만 보관했다. 로컬 산출물은 `manifest.json`, `results.jsonl`, `summary.json`,
`execution-records.json`, `bundle-provenance.json`, `answer-quality-review.json`,
`web-only-completion.json`으로 추적한다. 실제 Run 데이터나 원문을 이 문서에 복사하지 않았다.

평가용 worker·브라우저·frontend·backend·DB를 종료했다. 원래 사용자 앱의 150개 Run
요약·버전은 평가 전후 일치했으며, Agent 소스 해시도 평가 시작 시점과 일치했다.
v3 실제 평가는 실행하지 않았다.

4개 매개변수가 저장소 루트 상대 fixture를 찾지 못했다. 위 루트 실행에서는 모두 통과했다.
