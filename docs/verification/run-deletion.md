# 등록 Run 삭제 검증

2026-10-03에 승인한 후속 기능이다. 원본 v12.3.1에 없던 선택 Run·전체 등록 Run 삭제를 추가하며, 기존 프로토타입 동등성 범위를 확대해서 주장하지 않는다.

## 적용 범위

- 선택한 Run ID의 모든 버전·수치·그래프·연결 작업과 독점 관리 원본을 삭제한다. 전체 삭제는 현재 필터와 관계없이 확인창에 표시한 등록 Run 목록을 대상으로 한다.
- 저장된 의견·판단 기록이 사용하는 대상이 있으면 요청 전체를 차단한다. 일반 채팅 스냅샷은 유지하고 삭제를 허용하며, 삭제 대상인 현재 Agent 기준 Run·후보 집합은 자동으로 해제한다. 처리 중인 업로드·재처리가 있으면 삭제를 차단한다.
- 외부 업로드 원본, 다른 Run·작업이 공유하는 파일, 미등록 실패 작업을 보존한다.
- DB 삭제가 실패하면 원본을 유지한다. DB 삭제 후 파일 정리만 실패하면 그 상태를 응답하며 서버 재시작 때 정리를 다시 시도한다.
- 과거 업로드 요청 키는 빈 배치 접수 기록과 함께 유지한다. 같은 파일을 새 요청으로 업로드하면 재등록할 수 있다.

## 실행 결과

| 검사 | 결과 |
| --- | --- |
| `backend/gradlew -p backend test --console=plain` | 113개 통과, 실패·오류·스킵 0. 새 삭제 테스트 14개 포함 |
| `npm test` | frontend 98개, agent 32개, Node 34개 통과. 외부 기준 데이터용 agent 테스트 4개는 명시적 스킵 |
| `npm run typecheck`, `npm run lint`, `npm run build` | 통과 |
| `npm run verify:public-files`, `git diff --check` | 통과 |
| `npm run test:e2e` | 17개 통과, 외부 기준 비교 10개 스킵. 삭제 흐름 6개 포함 |

삭제 테스트는 독립 PostgreSQL과 인공 입력만 사용한다. 실제 실험 데이터 검증 모드에서는 삭제 E2E를 실행하지 않는다. 잠금 경쟁은 실제 PostgreSQL 잠금을 사용해 확인했으며, 공유 경로 보존·트랜잭션 롤백·파일 정리 실패 후 복구도 검증했다.

브라우저에서 390 / 800 / 1008 / 1440px 폭의 확인·취소·개수·선택 삭제·전체 삭제·재업로드와 판단 기록 보호를 확인했다. 일반 채팅에 등장한 Run은 삭제할 수 있고 채팅은 보존되며 현재 Agent 참조만 해제되는 흐름도 확인했다. 390×420px의 낮은 화면에서 차단 안내가 확인창 밖으로 넘치는 실패를 재현한 뒤, 삭제 확인창에만 높이 제한과 내부 스크롤을 적용해 전체 브라우저 검증을 다시 통과했다. 스크린샷·로그·결과 파일은 Git에서 제외한 로컬 검증 경로에만 남긴다.

기존 수용 검증의 D1–D5 유예는 유지한다. 삭제 기능 검증은 실제 150 Run의 전체 수치·원본 화면 동등성을 재검증한 결과가 아니다. 백엔드 테스트 종료 시 Hikari 종료 대기 경고가 있었으나 실패한 테스트는 없었다.
