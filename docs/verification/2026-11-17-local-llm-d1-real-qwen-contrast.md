## 출처와 정상 정답 확인

기존 DB의 `v2_localLLM` 요청15건·실제 Qwen 계획 응답18건을 출처로 삼았다. 모델은 Qwen3.5-9B GGUF Q4_K_M이며 실제 모델 응답ID와 사용량이 남아 있다. 사람이 처음부터 만든 고정 계획을 이번의 정상 자료로 사용하지 않았다.

- 현재 필드 형식에 맞는 저장 계획10개 중 서로 다른 질문5종에서 각각1개를 선정했다. 옛 requires 형식5개를 임의 변환하지 않았다. 같은 질문의 OFF/ON 반복을 다른 질문으로 세지 않았다.
- 선정5개 모두 실제 PLAN_INITIAL 응답이다. 원 응답을 현재 계약으로 읽은 계획, 저장 plan_revision, 당시 PLAN_REVIEW.reviewInput의 계획이 일치했다. 원문·이력·확인 문맥도 실제 검토 입력에서 그대로 가져왔다.
- 작업은 순방향 조회3개·에너지 범위 검색1개·이온 플럭스 하한 검색1개다. 이5종이 복잡한 Agent 작업 전체를 대표하지는 않는다.
- 원문과 각 수치·단위·연산자·인용의 대응을 직접 검토하고 정확한 기대값을 사전에 고정했다. 인용문이 실제 원문에 있으며 해당 조건을 뒷받침하는지 확인했다. 옛 d1의 PASS를 정답 근거로 삼지 않았다. 이 직접 검토는 Codex가 수행했으며 독립적인 사람의 별도 승인으로 표현하지 않는다.
- 오류를 주입한 입력의 인용 방식은 질문 전체 인용3쌍·조건 구절 인용2쌍이다. 인용은 어느 경우에도 수정하거나 제외하지 않았다.

실제 질문·Run 참조·요청/모델 응답ID·원 계획·원시 확률은 이 공유 문서에 복사하지 않는다.

## 바꾼 것과 그대로 둔 것

각 정상 계획을 복사한 뒤 plan 내부의 실행 숫자 leaf1개만 바꿨다. 압력·소스 전력·바이어스 전력·범위 상한·하한 비교값을 각각 대상으로 삼았다. 범위 상한은 하한보다 크게 유지해 구조 오류가 먼저 잡는 사례를 만들지 않았다.

원문·조건별 source.quote·요구사항 text/sources·source.message_key·단위·배율·연산자·의존/요구사항 연결은 그대로다. 정상과 오류 모두 현재 PlanDraft와 기존 구조 검증을 통과했고, 검증기가 계획을 고쳐 주지 않았음도 확인했다.

검토 문맥·hash·program_effects는 기존 코드로 재생성해 바뀐 실제 숫자를 반영했다. 기대값·정답 사유·변경 경로·normal/bad 표식·정상/오류 diff는 모델 입력에 보내지 않았다. 각 계획은 독립적으로 검토했다.

입력은 기존 v2.4 방식이다. 원문·계획·인용은 모두 보존하고, **기존 도구·지표 설명 선별만 적용**했다. 앞선 execution-data-focus-v1의 인용 필드 제외, 지시서 재구성, 새로운 번역·요약·선택지·임계값 변경은 적용하지 않았다.

## 해석과 남은 한계

올바른 인용을 보존한 실제 형태의 계획에서도 d1은 숫자 차이를 놓치거나, 다른 검사에 누락을 지적하거나, 사유를 다르게 분류했다. 이번 결과를 ‘Qwen 인용이 잘못돼서 생긴 문제’만으로 설명할 수 없다. 다만 모델 자체·복잡한 입력·검사 범위 지시서·선택지 표현 중 어느 요인이 주원인인지는 이 한 구성의 실험만으로 분리되지 않는다.

인용을 보존한 구성과 제외한 구성을 같은 실제 자료에서 비교하지 않았다. 따라서 인용을 제외해도 안전하다거나, 보존 자체가 정확도를 높였다는 인과 결론을 내리지 않는다. 부분 인용2쌍과 전체 인용3쌍은 조건 종류도 달라 두 유형의 우열도 판단하지 않는다.

이번 정상5/오류5는 수치 불일치 검사다. 긴 복합 요청·새 단위/경계/정렬/대상/기준 오류·전체40문항·재계획 후 최종 답변의 성적으로 확대하지 않는다. 실패를 이유로 지시서/선택지/입력을 바꿔 추가 실행하지 않았다. 공용 최종 구성은 기존 v2.4이며 v2.5 정확도 개선 완료로 기록하지 않는다.
