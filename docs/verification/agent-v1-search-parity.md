# Graph v1 순·역방향 검색 패리티 수정

2026-10-05. 브랜치 `feat/agent-graph-v1`, 최초 구현 `79ce343` 이후 수정이다.

## 원인과 변경

사용자 질문 “Ion Flux는 높게, Mean Ion Energy는 150–160 eV에 가깝게 후보를 찾아줘”를 기존 프롬프트와 계획 F4/X6이 soft `target_range`로 지정했다. 에너지 필수 조건이 없어 공통 후보가 150개였다. LLM이 명시된 기존 지침을 따른 것이며 범위 필터 구현 자체의 누락은 아니었다. 사용자의 원본 결과 유지 지시에 따라 계획·프롬프트·원문 대응 검증을 함께 수정했다.

이제 명시된 범위는 “가깝게/near”를 포함해 기본 `between` 필터다. 범위 밖 후보를 허용한다고 명시할 때만 soft 목표로 처리한다. 허용 부정 표현과 명시적 목표 우선순위 위반은 추가 확인으로 넘긴다. 등록 도구·모델·추론 설정은 그대로다.

별도 `SearchCard`가 기존 `answer-markup.js`와 프로토타입 스타일을 우회한 것도 UI 차이의 원인이었다. v1의 저장 결과를 기존 순·역방향 표현 계약으로 전달하도록 교체했다. 순방향은 조회 결론·조건 세 칸·관찰 지표 카드, 역방향은 공통/목표/개별 조건 탭·근접도·기준값·내부 스크롤·원래 버튼을 사용한다. 사용하지 않는 `SearchCard`, 카드 선택/목록/탭 스타일을 삭제했다. v1 비교·설명·진행 상태 화면은 계속 사용한다.

JS fallback 해석·검색·계산을 신규 실행 경로에 넣지 않는다. Python이 필터·순서·근접도를 계산하고 exact Run 버전별 평가를 `candidateEvaluations`에 저장한다. 프런트엔드는 다시 검색하거나 점수를 계산하지 않는다. 같은 버전의 반복 후보 표현은 한 번만 만들며, 공유 markup 컴포넌트를 분리해 순환 import를 제거했다.

## 결과·기록 계약

- 기본 탭은 모든 필수 조건을 만족하는 공통 결과다. 목표별 전체 후보는 별도 탭이며 공통 조건 충족으로 표시하지 않는다.
- 외부 원본의 사용자 예시에서 공통 결과 5개, Flux 목표 탭 150개, 에너지 조건 탭 5개를 유지한다. 공통 결과의 ID·순서·측정값·근접도·목표 문구를 원본과 비교했다.
- 상세 조회·이어질문·판단 저장은 snapshot의 정확한 `runVersionId`를 사용한다. 화면에 내부 UUID를 별도 버전 문구로 노출하지 않는다.
- 완료된 이전 답변은 재계산하거나 덮어쓰지 않는다. 이전 프롬프트가 범위를 soft 목표로 해석한 기록에는 안내를 붙인다. 수정된 검색은 새 질문에서 적용된다. 저장되지 않은 이전 근접도는 비가용으로 표시한다.
- 새 결과는 `schemaVersion: 1`의 additive 필드다. 배포 식별자는 `graphBuildId: v1-2026-10-05.3`, `promptVersion: interpret-2`다. 기존 미완료 checkpoint의 다른 설정 재개는 기존 fingerprint 검증이 차단한다. DB 마이그레이션은 없다.

UI 대조는 변경하지 않은 외부 v12.3.1에 동일한 소량 인공 데이터를 공급하고 동일 브라우저·시각·폭·locale·timezone을 고정했다. 전체 문구와 주요 요소 bounding box를 비교하며 위치/크기 오차는 브라우저의 1/64px 이하로 제한했다. 원본 화면 전체의 픽셀 일치나 모든 질문·곡선의 일치를 주장하지 않는다. 로컬에 스크린샷을 보존했으며 Git/PR에 실데이터를 게시하지 않는다. 외부 원본 비교는 opt-in이고 CI에는 인공 데이터 UI 회귀 네 건을 추가했다.

최종 프롬프트 해시 `2764562c262e6b8f77d96ae4fd242d5c143eca407097ec19a26f409a4f887c5a`로 역방향 46개 질문을 각각 세 번 호출했다. **134/138(97.10%)**, 필수 항목 **872/882(98.87%)**, 잘못된 실행 허용 0건, API 오류 0건이다. 사용자 예시는 3/3 통과했다. 네 실패는 단위/값 변경 세 건과 잘못된 operation 한 건으로, 모두 확인 질문으로 차단했다. 전 사례 일치 조건 때문에 실행기는 exit 1이며 전체 통과로 표시하지 않는다. 마지막 부정어 guard 수정 후 저장 응답을 재채점한 결과도 같았다. 이 재채점은 새 모델 호출이 아니다.

최초 구현의 전체 140개 질문 평가와 이번 역방향 46개 신규 평가를 혼합하지 않는다. 전체 141개 질문을 수정 프롬프트로 세 번 호출하는 평가는 실행하지 않았다. 과학적 설명 정확도는 별도 도메인 전문가 검토가 필요하다.

실제 모델과 실제 150 Run을 한 번에 연결하는 추가 검증은 자동 승인 검토가 데이터 외부 전송 우려로 거절하여 실행하지 않았다. 실제 모델 종단 검증은 독립 인공 DB에서, 실데이터 대조는 로컬 프로세스 메모리에서 각각 수행했다. 사용자 대화·실제 DB는 테스트로 변경하지 않았다.

로컬 증거는 Git에서 제외한 `agent/python/.runtime/` 및 `/tmp/kplasma-agent-v1-ui/`에만 둔다. Java 21 또는 Playwright 기본 Chromium 경로가 발견되지 않은 초기 검증 실행은 환경 오류로 실패했고, 설치된 경로를 명시한 재실행으로 통과했다. 이를 제품 테스트 통과와 혼동하지 않는다.

원격 CI 첫 실행에서는 기존 Catalog 메뉴 복원 테스트가 화면 버튼 표시 직후 effect의 원본 파일 조회를 기다리지 않고 검사하여 실패했다. 해당 assertion에 `waitFor`를 적용해 요청 발생을 기다리며, 이전 버전 작업의 원본을 조회하지 않는 검증은 유지했다. 제품 Catalog 동작은 변경하지 않았다.
