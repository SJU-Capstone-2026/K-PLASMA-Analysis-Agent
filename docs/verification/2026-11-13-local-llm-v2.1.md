# LocalLLM_v2.1 체크포인트

`LocalLLM_v2.1`은 현재 구현을 보존하는 Git 체크포인트 이름이다. API의 그래프 식별자는 `v2_localLLM`을 유지한다.

## 보존한 구현

- 기존 v2를 물리적으로 복제한 독립 로컬 그래프와 같은 `submit_plan`·PlanDraft·최종 응답 계약을 유지한다.
- Qwen3.5-9B GGUF Q4_K_M / llama.cpp b12317 Metal, 계획 생각ON, 답변 생각OFF와 d1-2B Q8_0 검토를 사용한다.
- Qwen24K·입력16K·batch/ubatch256, d1 context32K·batch/ubatch16000, 순차 상주와 기존 준비 판정 기준을 유지한다.
- 공통5173 웹·8080 backend·기존 DB에서 버전을 선택하며, 상용/로컬 워커 키와 기억의 출처 경계는 분리한다.
- 보호 대상 그래프 원본76개 보존 파일의 hash와 초기 복제 증거가 그대로임을 확인했다. 과거 대화·실험 데이터·모델 파일은 변경하거나 커밋하지 않는다.

## 정리한 코드

현재 그래프가 호출하지 않는 로컬 `ModelClient`의 이전 Responses API·이전 도구 선택·continuation 메서드를 제거했다.
실제 사용하는 native 도구 호출, JSON Schema 답변, 스트리밍·오류 처리 코드는 유지했다. 계획 입력 직렬화는 기존과 같은 JSON을 생성한다.

현재 워커·평가·측정은 모두 llama.cpp native counter를 제공한다.
사용하지 않는 Hugging Face tokenizer 경로와 이에 전용인 테스트5개·Transformers를 포함한 의존성17개를 제거했다.
설정되지 않은 Qwen counter는 원문 전송 전에 명확히 거부하며, 이 동작의 plan/answer 테스트2개를 추가해 실패부터 확인했다.
기존 설정 식별용 tokenizer 경로 필드는 체크포인트 fingerprint 호환을 위해 유지한다.

의도적으로 복제한 그래프·도메인 모듈과 보안·검증 코드는 삭제하거나 공유 모듈로 합치지 않았다.
공통 기억 인증의 조회 범위를 더 좁히는 제안은 현재 동작을 단순히 보존하는 정리보다 변경이 커 이번에 적용하지 않았다.
계획 지시서 수정·캐시 저장/복원·생각 예산 조정 등 응답 속도 개선도 적용하지 않았다.

새로 실행한 위 테스트는 총1,112개다. Node의 인공 세션3개는 최초 실행에서 샌드박스가 localhost listen을 막아 실패했고, 로컬 포트를 허용한 동일 전체 명령으로 재실행해 통과했다.
공통 backend의 앞선 전체260개 테스트 통과 기록은 그대로 유효하며, 이번 정리에서 backend 구현은 바꾸지 않았다.
실제 모델 호출·앞5문항/전체40문항 재평가·DB 복구 재실행·실행 서비스 재기동은 하지 않았다.

## 남은 제한

앞5문항 자동 정답5/5는 정리 전 실제 평가 기록이다. 이번 정리가 정확도나 응답 시간을 개선했다고 주장하지 않는다.
최초 계획은2/5만 즉시 채택됐고 나머지3개는 재계획1회 후 통과했다. Q03의 결측 사유 설명과 작은 화면 표 가독성 문제도 유지한다.
통합 뒤 로컬 워커 재기동은 호스트 메모리 경고로 준비 검사에서 중단된 상태이며, 현재 새 질문의 실행 준비 완료를 보증하지 않는다.
모든 원시 평가 자료·질문·답변·스크린샷·DB 백업·비밀 설정은 Git 제외 경로에 보존한다.
