# LocalLLM v2.7 Flash 계획 검토 개선

## 핵심 요약

- **검토 하네스** — 기준 Run·경향 축·실행 전제의 판정 기준을 검사별로 명시했다. 범위 지시서에 양 끝 포함 여부를 판정하는 짧은 예시 하나를 넣었다.
- **실제 검사 자료** — 범위에는 실행 연산자와 원문을, 비교에는 Run의 출처와 출력 목록을, 확인 요청에는 선택창 목록을 전달한다. 기존 숫자 검사의 입력 축소를 v2.7에 통합했다.
- **코드 판정** — 명확한 정렬·비교 대상, 단독 조회에서 요청하지 않은 확인·비교, Run 참조 목록의 물리 단위 오류를 검사한다.
- **로컬 검토 모델** — LiquidAI d1-2B MLX8에서 Perplexity Decider Flash v1.2 MLX4로 전환했다. [Flash 모델 카드](https://huggingface.co/perplexity-ai/pplx-decider-flash-v1.2)

같은 Flash에 저장된 첫 계획 36개를 다시 검토시켜 **20/36 (55.6%) → 34/36 (94.4%)**을 얻었다. 정상 통과는 **18/26 → 26/26**, 오류 검출은 **2/10 → 8/10**, 평균 검토는 **5.65 → 4.81초**였다. 별도 웹 40문항에서는 C01 채점표 보정 기준으로 이전 d1 **18/40**, 최종 Flash **30/40**이 통과했다.

## Flash를 고른 이유

- Flash v1.2는 Qwen3.5-4B 기반의 선택지 판정 모델이다. 판정과 선택지별 확률을 받는 기존 검토 구조에 연결할 수 있고, MLX 4비트 변환으로 Apple Silicon에서 구동했다. 기존 Qwen 9B가 계획과 답변을 만들고 Flash가 검토하는 역할을 분리했다. [Flash 모델 카드](https://huggingface.co/perplexity-ai/pplx-decider-flash-v1.2#request-schema)
- 동일한 저장 계획을 비교한 초기 교체 실험에서 Flash는 d1이 정상 바이어스 조건을 반려했던 Q07을 통과시켰다. B04의 경계 오류는 두 모델 모두 놓쳤다. 모델만 교체했을 때 보류는 2건에서 10건으로, 계획당 평균 검토 시간은 d1 로그 3.58초에서 Flash 5.65초로 늘었다. 채택 판단에는 아래의 검사 개선과 전체 웹 평가 결과를 함께 사용했다.

## 평가 기준

- 이전 40문항 웹 평가에서 검토까지 도달한 첫 계획 36개를 재사용했다. B07·C03·C05·H06은 검토 가능한 계획이 없었다.
- 기준 답은 질문·실행 계획·기존 평가 기준·실행 코드를 대조해 정상 26개와 오류 10개로 고정했다. 정상 계획은 `PASS`, 오류 계획은 해당 오류를 맞는 검사에서 지적한 `ISSUE`만 정답으로 인정했다.
- C01은 실제 요청대로 전체 검색 결과를 비교하는 계획이다. 이전 비교 기준에서 유효한 검색 결과 하나를 빠뜨린 점을 반영했다. I03은 기존 평가 기준에서 바이어스 전력을 비교 지표로 요구하므로, 조건 메타데이터에만 제공되는 경우는 오류로 유지했다.
- v2_localLLM의 계획 검토 상태를 켜고, Flash v1.2 MLX4 단일 처리로 재검토했다. 이 문항들에 대해 Qwen을 호출하거나 웹 평가를 다시 실행하지 않았다. 인공 대조군은 36개 정확도에 포함하지 않았다.

## 원인과 변경

| 검토 항목 | 확인한 문제 | 적용한 방식 |
|---|---|---|
| 기준 Run | 기준이 필요 없는 비교에서 정상 `null`을 `UNCLEAR`로 판단 | 기준 없이 비교하는 조건을 짧게 명시했다. 계획에 기준 Run이 실제로 있으면 참조와 요청의 일치만 확인한다. |
| 경향 축 | 단순 비교, 기준 지정, 파형 표시를 경향 축 요청으로 오해 | 공정 조건에 따른 변화 요청과 일반 비교를 나눠 설명한다. |
| 숫자 범위 | 짧은 인용에서 양 끝값 제외 요구를 놓침 | 검색 하나의 명시적 범위에 전체 질문과 실행 경계 연산자를 표시한다. 여러 검색 또는 단위 추론이 필요한 범위는 기존 검사별 인용을 사용한다. |
| 사용자 확인 | 전체 계획 안의 불필요한 선택창을 놓침 | 실제 계획에 들어 있는 확인 단계 목록만 전한다. 기존 구문으로 독립 조회·정렬 요청이 확인되면 추가 선택창과 불필요한 비교를 코드에서 지적한다. |
| 비교 대상·결과 | 선택된 Run과 검색 후보 전체를 혼동하고 추가 분포를 허용 | 비교 대상 출처와 실제 비교 지표·그래프 종류를 검사별로 표시한다. 복잡한 참조는 기존 참조 자료를 유지한다. |
| 실행 전제 | 참조 목록을 기다리는 정상 조건과 참조에 물리 단위를 요구하는 오류를 구별하지 못함 | 전제 조건의 범위를 명시한다. 참조 목록에 물리 단위를 요구해 실행이 막히는 경우는 코드에서 지적한다. |

## 실험 경과

| 실험 | 관측과 결정 |
|---|---|
| 기준 Run 문구만 변경 | 기준 검사 17개에서 `UNCLEAR` 12 → 0. 계획 정확도 23/36. 추가된 기준 Run을 놓쳐 기준이 있을 때의 문구를 다시 분리했다. |
| 선택창 문구만 변경 | `UNCLEAR` 11건으로 늘어 제외했다. 실제 확인 목록만 제공하면 B08의 선택창 오류를 검출했다. B06의 단독 조회는 코드에서 확정했다. |
| 숫자 문구만 변경 | I05의 정상 범위는 살렸지만 B04는 여전히 통과했다. 실행 경계를 펼치자 B04는 `BOUNDARY_CHANGED` 96.5%로 바뀌었다. 전체 질문이 Q08의 두 그룹을 혼동시키는 경로는 제외했다. |
| 비교 대상·출력 문구만 변경 | 실질적인 오류 검출 개선이 없었다. 입력 항목을 직접 표현하자 M04의 대상 변경과 M03의 미요청 IEAD를 찾았다. |
| 문구 변경 합산 | 28/36이었으나 실제 오류는 2/10에 머물렀다. 이 구성은 적용하지 않았다. |
| 최종 구성 | 실제 모델 경로에서 36개를 다시 검토했다. 기준·경향 축·범위·선택창의 별도 인공 대조군 16개도 기대 판정과 일치했다. |

| 지표 | 기존 Flash | 개선 Flash |
|---|---:|---:|
| 계획 정확도 | 20/36 (55.6%) | 34/36 (94.4%) |
| 정상 계획 통과 | 18/26 | 26/26 |
| 실제 오류 검출 | 2/10 | 8/10 |
| 오류 계획 통과 | 3 | 2 |
| 보류 | 10 | 0 |
| 평균 검토 시간 | 5.65초 | 4.81초 |
| 평균 검토 입력 토큰 | 3,054 | 2,582 |

B01·B04·B06·H01·M03·M04에서 실제 오류를 새로 검출했다. H03의 미요청 해석과 I03의 명시적 바이어스 비교 지표 누락은 통과시켰다. B08은 실제 정렬 누락과 미요청 선택창에 더해 관련성이 낮은 지적도 남겼다.

## 별도 웹 40문항 평가

각 문항을 새 대화에서 한 번 제출해 Qwen이 새 계획을 작성했다. 검토·캐시 ON, Docker 1.5GiB와 `v2_localLLM`을 사용했다. 응답 시간은 접수부터 종료까지이며, 정답 수는 고정 자료의 자동 채점이다.

| 지표 | 이전 d1 | 최종 Flash |
|---|---:|---:|
| 최초 통과 | 15 | 21 |
| 재계획 후 통과 | 3 | 9 |
| 실패 | 22 | 10 |
| 최종 통과 | 18/40 (45%) | 30/40 (75%) |
| 총 재계획 | 38 | 22 |
| 검토 지적 직후의 재계획 | 21 | 4 |
| 전체 응답 평균 | 110.1초 | 100.7초 |
| 전체 응답 중앙값 | 119.9초 | 84.7초 |
| 둘 다 통과한 18문항의 평균 | 55.6초 | 64.7초 |
| 최초 계획 캐시 적중 | 38/40 | 39/40 |

Flash 원래 채점은 29/40이었다. 저장 응답을 재사용해 C01의 비교 기준을 복원된 150개 Run에 맞춰 양쪽을 다시 채점했다. C01은 Flash에서 최초 통과로 바뀌었고 d1에서는 실패였다. 응답 시간은 원래 웹 실행의 계측값을 사용했다.

웹의 남은 10건에는 Flash가 이미 충족된 정렬·선택 조건을 반려한 B08·H02, Flash 검토 전에 연결 검사를 통과하지 못한 C03·C04·C05·H03, 동일 출력 지표가 중복되어 비교를 실행하지 못한 M03, 답변 작성·검토 범위 문제가 있었던 H05·I01·I03이 포함된다. 설명·해석 6문항은 독립적인 내용 검토가 남아 있다.

## 로컬 실행 확인

- `cd agent/python && .venv/bin/python -m pytest -q -c pytest-v2-local-llm.ini`에서 831개 통과, 8개 제외였다.
- `node --test scripts/agent/local-llm.test.mjs scripts/agent/measure-local-llm.test.mjs`에서 8개가 통과했다.
- Docker 1.5GiB 설정에서 인공 입력을 사용한 로컬 준비 검사 7개가 통과했다. 시스템 메모리 피크는 17.65GiB였고, 메모리 압력 표본 260개가 모두 정상이었으며 스왑 증가는 0이었다. Qwen 계획 캐시는 디스크에서 10,643토큰을 복원했다.
- 로컬 워커가 Flash v1.2 MLX4 단일 처리로 시작했다. 계획 검토와 Qwen 생각모드·계획 캐시가 활성화된 설정을 확인했고, 로컬 웹과 백엔드가 응답했다.

세부 실험의 변경 가설·판정·토큰·시간은 로컬 실험 장부와 문항별 결과에 남겼다. 원시 질문·계획·Run 데이터가 포함된 산출물은 Git에서 제외했다.
