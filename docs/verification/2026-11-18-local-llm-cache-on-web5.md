# LocalLLM_v2.5.2 최종 평가 — Qwen 캐시 ON·앞 5문항 웹 비교

사용자 지시에 따라 이번 무주입 웹 평가를 **v2.5.2의 최종 평가 기록**으로 둔다. 기존 Q02 설명·고의 참조 오류 복구 검증 1건은 별도로 보존하며 성적을 합산하지 않는다. 코드 기준은 `e58ff84` 이후 캐시 준비 검사 분리를 포함한 후속 작업본이고, 추가 변경은 기록 시점에 미커밋이다.

v2.5.2(`e58ff84`)를 기준으로 실제 개발 실행의 Qwen 계획 KV 캐시를 ON으로 저장했다. 사용자 승인에 따라 캐시 준비 여부와 d1 의미 판정 성적을 분리하고, 새 메모리 검사를 통과한 뒤 기존 40문항 중 Q01~Q05를 새 대화에서 한 번씩 웹으로 제출했다. 최종 5/5 통과, 최초 통과 3건·재계획 후 통과 2건이다. 직전 OFF의 평균 종료 시간 92.915초에 비해 이번 ON은 50.109초였다.

## 변경과 유지 범위

- 실제 워커의 비공개 환경 파일에 `QWEN_PLAN_CACHE_ENABLED=true`를 저장하고 Qwen을 같은 `--slot-save-path`로 실행했다. 일반 워커를 사용하며 모델 서버·워커의 재시작 인자도 비공개 실행 폴더에 보관했다. 평가 종료 후 OFF로 복원하지 않는다. 설치 예시의 opt-in 기본값은 별개다.
- 인공 준비 검사에서는 저장·복원·실제 토큰 재사용·실행 수치 보존과 d1 응답 계약을 확인한다. `PlanReviewResult` 전체를 검증해 정상적인 `PASS`/`ISSUE`/`UNCLEAR` 응답을 인정하고, 의미 판정 성적은 `semantic_review_passed` 및 실제 검사·점수로 별도 보존한다.
- 누락·불완전·모순된 d1 응답, `UNAVAILABLE`/`SKIPPED`, 캐시 실패, 심각한 메모리 상태는 계속 준비 실패다. 실제 요청에서 d1의 `ISSUE`를 PASS로 고치지 않는다.
- Docker VM 1536MiB, 개발 메모리 정책, d1 Q8+MLX 단일 처리, 생각 모드와 생성 설정, 기존 그래프·최종 응답 양식, 최대 2회 재계획·1회 답변 재작성을 유지했다. Qwen 지시서·도구 스키마와 d1 지시서·선택지는 변경하지 않았다.
- 기존 로컬 웹 인증이 만료되어 같은 애플리케이션 인자와 인증 정책으로 연결을 갱신했다. 인증 유효기간과 호스트 제한은 그대로다.

## 웹 결과 — 문항별 1회

전체 시간은 DB의 요청 생성부터 실행 종료까지이며, OFF Q03의 실패 종료 시간도 포함한다. OFF는 저장된 직전 v2.5.2 결과를 사용했고 이번에 다시 실행하지 않았다.

## 캐시와 시간 해석

- 최초 계획 5/5, 재계획 포함 7/7에서 디스크 캐시 복원과 실제 적중을 확인했다. 각 호출이 10,491토큰을 재사용했다. 새 질문마다 Qwen이 계획을 새로 생성했다.
- 최초 계획 5건의 평균 입력 처리: **32.874887초 → 0.470928초**, 98.57% 감소.
- 최초 계획 5건의 평균 생성: 28.695840초 → 24.824284초. 생성 길이와 내용이 달라 이 차이를 캐시 효과로 단정하지 않는다.
- 두 회차 모두 성공한 동일 4문항(Q01·Q02·Q04·Q05)의 평균 전체 시간은 **75.028540초 → 54.264687초**, 27.67% 감소했다.
- 전체 평균의 46.1% 감소에는 OFF Q03의 재계획 시간 초과와 이번 생성 계획·복구 경로 차이가 섞여 있다. 캐시가 직접 줄인 입력 처리와 전체 종료 시간은 구분한다.

실제 150 Run·버전의 해시와 기존 대화 턴 해시를 보존했고 새 요청·턴은 각각 5건만 추가됐다. 실제 5개 그래프 상태 모두 `plan_review_enabled=true`를 관측했다. 웹 모델 호출은 최초 계획 5·재계획 2·계획 검토 5건이다. 오류 주입, 추가 문항, 별도 API 문항 평가는 없다. 기존 프런트엔드·클라우드 워커는 그대로 두었다.
