# LocalLLM_v2.2 — 선행 출력 조건 이름·지침

기준은 `7803b29`(LocalLLM_v2.1)다. 사용자가 지정한 개선1번만 구현한다.
로컬 그래프 식별자는 `v2_localLLM`을 유지한다. 새 commit/tag는 만들지 않았다.

## 문제와 변경

앞선5문항에서 최초 계획3개가 조회 자신의 `ionFlux`·`meanIonEnergy`·`iedWidth`를 `requires`로 요구했다.
기존 검증이 실행 전에 차단하고 재계획을 요청했으므로 실제 그래프 순환 실행은 아니었다.
필드 의미의 혼동이 원인이라는 설명은 추정이며 모델 내부 원인을 입증한 것은 아니다.

로컬 계획의 필드를 `required_prior_outputs`로 변경했다.
Pydantic 필드 설명과 Qwen 계획 지시서에 사용자 작업·단계 순서·입력 연결·선행 출력 조건의 차이를 명시했다.
자기/후속/비선행 단계 금지, 첫 리터럴 조회의 빈 배열, 도구별 출력 키, 정확한 count와 nullable 조건을 설명한다.
계획 생성·재계획·실행 바인딩·d1 검토의 키와 검토 경로가 같은 이름을 사용한다.

과거 `requires` 입력은 Pydantic alias로 읽고 새 계획은 새 이름으로 출력한다.
두 이름을 함께 보내면 한쪽이 null이어도 거부한다. 기존 JSON 기본값 처리에서 충돌이 지워지지 않게 보완했다.
null 기본값은 최상위 steps 배열의 단계 객체에서만 처리한다. 잘못된 위치의 필드는 삭제하지 않고 거부한다.
과거 이름으로 입력한 인자 오류도 새 표준 이름의 경로로 안내하며, 원본 모델 인자와 충돌한 추가 필드의 위치는 보존한다.
잘못된 자기 참조를 코드가 삭제해 통과시키지는 않는다. 기존 의미 검증이 계속 거부한다.

## 보존한 동작

- 자기/미래 참조·존재하지 않는 출력·단위·정확한 개수·입력 형태·enum·추가 필드 검사를 유지한다.
- 그래프 노드·간선·실행 순서 알고리즘, 재계획 예산, d1 승인과 최종 응답 schema를 유지한다.
- 과거 DB·대화·계획 행을 변환하지 않는다. 인공 backend 테스트에서 구/신 JSON의 각 저장 응답 전체와 첫 행의 구 필드명 보존을 확인했다.
- 다른 fingerprint의 미완료 checkpoint는 기존 `RECOVERY_VERSION_MISMATCH`로 차단한다. 버전 간 자동 재개 기능을 추가하지 않았다.
- v2/v3 원본과 동결 복제 증거는 수정하지 않았다. 모델·생각 예산·입력 한도·Docker·메모리 준비 기준·캐시도 변경하지 않았다.

로컬 계획 schema는 [별도 계약 파일](../contracts/agent-v2-local-llm.plan.schema.json)로 내보냈다.
PlanDraft.schema_version은2, native 계약 식별자는 `native-submit-plan-chat-v2`다.
동결 계약 검사는 지침 추가 구간·필드 설명·이름만 되돌려 기존 계약과 비교한다. 동결 기준 파일은 재생성하지 않았다.

## 실제 모델 확인의 한계

현재 private 설정의 기존 준비 검사를 시도했으나 `LOCAL_MEMORY_PRESSURE`로 차단됐다.
인공 문장의 Qwen 계획 생성·d1 검토 호출은 시작하지 않았다. 준비 판정을 우회하거나 다른 앱을 종료하지 않았다.
따라서 이번 결과는 계약·실행·저장 호환 검증이며 실제 첫 계획 성공률이나 응답 시간 개선을 입증하지 않는다.
40문항/앞5문항 재평가, 실제 DB 수정, 서비스 재시작과 배포는 수행하지 않았다.
기존5/5 정답과 최초 즉시 채택2/5는 v2.1 이전 평가 기록으로 남긴다.

원시 로그·메모리 결과·비밀 설정은 Git 제외 경로에 보존한다.

## 최종 검토

별도 읽기 전용 코드 검토1회를 수행했다. 중요한 발견2개를 회귀 테스트7개의 실패로 재현하고 한 번의 수정 단계에서 해결했다.
잘못된 위치의 null 필드6개는 거부하고, 구 이름의 잘못된 count는 새 오류 경로로 표시한다. 정상 null2개와 충돌3개 검사도 유지한다.
수정 후 전체 로컬405개 통과를 확인했다. 모델 재평가는 준비 기준 차단 때문에 보류했고 서비스·실제 DB는 변경하지 않았다.

보류한 경미한 테스트 보강1건: 두 번째 revision 저장 뒤 DB에서 다시 읽은 첫 JSON 전체와 원본을 대조하는 검사는 추가하지 않았다.
현재 검사는 각 저장 응답 전체와 두 행의 필드명을 확인한다. backend 제품 구현은 이번에 수정하지 않았다.
