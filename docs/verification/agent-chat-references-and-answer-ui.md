# 답변 표시 정리와 다중 Run 채팅 참조 검증

## 변경 범위

- 일반 답변과 `compare_runs`에서 고정 요약 문구 및 하단 `질문 해석·추가 입력`을 표시하지 않는다. 일반 답변의 `LLM 일반 지식 기반` 배지도 제거한다.
- 비교의 계산값·계산 근거·개별 해석의 가정과 한계·비가용 안내는 유지한다. 저장된 과거 답변 스냅샷은 수정하지 않는다.
- 순방향/역방향 결과의 Run 버튼을 `채팅에 추가하기`로 바꾸고, 기존 참조에 누적한다. 전체 후보 추가도 같은 정책을 사용한다.
- 개수 제한 없이 서로 다른 Run을 담을 수 있다. 동일 Run은 한 태그로 유지하며 명시적으로 다시 누른 카드의 정확한 버전을 사용한다. 태그별 제거와 전체 해제를 지원한다.
- 입력창의 태그 열 수는 가용 폭에 맞춘다. 삭제 버튼이 기존 분석 버튼의 최소 폭을 상속해 Run 이름을 가리지 않도록 크기를 분리하고, 긴 이름은 툴팁으로도 확인할 수 있다.
- 참조 변경은 기존 직렬 저장 큐에서 최신 서버 상태를 읽은 뒤 적용한다. 빠른 연속 추가에서도 앞선 참조를 덮어쓰지 않는다. 여러 Run을 담았다는 이유로 기준 Run을 자동 지정하지 않는다.
- 참조 저장 중 분석을 누르면 대기 중인 저장을 마친 뒤 질문을 한 번 전송한다. 기존에는 저장 작업의 subscription 무효화가 새 전송을 취소할 수 있었다. 이 상황을 재현하는 회귀 테스트의 실패를 확인한 뒤 전송 시작 순서를 수정했다.

사용자 요청으로 기존 프로토타입의 단일 참조 교체와 고정 문구를 변경한다. 분석 페이지의 개별 Run 이동 동작, API/DB 계약, 모델 프롬프트, 수치 계산은 변경하지 않는다.

새 통합 테스트는 연속 추가·중복 클릭·개별 제거·전체 해제·reload 복원·정확한 참조 버전 전송·과거 turn 불변성을 확인한다. 저장 응답을 보류한 상태에서 즉시 분석을 눌러도 모든 참조를 포함한 요청이 한 번만 전송되는지 검증한다.

브라우저에서는 390 / 800 / 1008 / 1440px 폭으로 답변의 불필요한 문구 제거, 8개 참조 누적과 접힌 태그 제거, reload 및 전송을 확인했다. 태그 표시 보완 후 전체 브라우저 검증을 재실행했고 같은 12 통과/8 생략 결과를 확인했다. 페이지·답변·입력 영역의 가로 넘침과 브라우저 런타임 오류가 없었으며, 검증용 Run 이름이 삭제 버튼 때문에 잘리지 않는지도 확인했다. 스크린샷은 인공 데이터만 사용해 로컬 임시 디렉터리에 보관했다.

이번 로컬 검증은 프론트 변경 범위이며 실제 LLM/Phoenix 호출, 실제 실험 데이터 비교 및 부하 테스트는 수행하지 않았다. 모델과 서버 계산이 변경되지 않았으므로 성능 개선율은 산출하지 않는다.

## 반영 후 확인

프론트 재시작 후 서로 다른 Run 세 개 이상을 담고 중복 추가·개별 제거·reload를 확인한다. 느린 참조 저장 중 분석해도 질문이 누락되거나 다른 버전으로 실행되지 않아야 한다. 저장 실패는 기존 오류 안내와 서버 상태 복구 정책을 따른다.
