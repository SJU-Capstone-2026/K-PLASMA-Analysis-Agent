# LocalLLM v2.5.2: 재계획 입력과 지시서 정합성

릴리스 기준은 v2.5.1(`c061314`) 이후의 v2.5.2다. 이 문서는 재계획 연결을 먼저 수정한 단계의 검증 기록이다. 뒤이어 적용한 근거 선택·참조 생성과 최종 오류 복구 성공은 [v2.5.2 근거 선택형 설명 검증](2026-11-18-local-llm-selected-values.md)에 구분해 기록한다.

d1 의미 검토에서 반려된 계획을 `rejected_plan`으로 전달하고, 지적 항목을 읽는 방법을 Qwen 계획 지시서에 명시했다. 실제 웹 Q02 한 건은 최초 d1 검토 PASS·재계획 0회였으나, 추가 설명 작성이 재작성 후에도 검증되지 않아 최종 PARTIAL 및 기존 채점 기준 실패였다. 전체 응답은 154.79초다. 실제 웹에서 재계획이 발생하지 않았으므로 재계획 복구 효과까지 검증됐다고 해석하지 않는다.

## 문제와 수정

기존 의미 검토 반려 경로는 반려된 계획을 `previous_plan`에 넣었지만 지시서는 이를 마지막 승인 계획이라고 설명했다. `rejected_plan`은 형식 오류에만 사용됐고, `plan_review_feedback`를 읽는 방법은 공통 계획 지시서에 없었다.

- 현재 revision의 d1 반려 계획을 `rejected_plan`으로 전달한다. 이때 `previous_plan`은 null로 두어 계획을 중복 전송하지 않는다.
- 형식 오류 재계획은 기존대로 `rejected_plan`과 `validation_error`를 사용한다. 이때 과거 의미 검토 지적이 섞이지 않도록 한다.
- 지시서에서 `failed_checks`, `issues`, 원문 인용과 실제 실행 입력 경로·값을 대조하도록 안내한다. `missing`만 보고 원문과 일치하는 숫자·단위를 임의 변경하거나 조건을 삭제하지 않도록 명시했다.
- `previous_plan`의 설명을 저장된 참고 계획으로 바로잡았다. `base_revision`도 의미 검토 승인 여부와 별개의 저장 revision임을 도구 스키마 설명과 내보낸 계약 문서에 함께 반영했다.

그래프 노드·간선·분기·최대 재계획 2회·답변 재작성 1회·실행 도구·최종 응답 스키마는 유지했다. AST 대조로 변경이 기존 `request_plan`의 모델 입력 구성에 한정됨을 확인했다. 계획 스키마도 설명문 이외의 차이가 없다. 변경 전 보호 대상 그래프는 수정하지 않았다. d1 지시서·선택지·모델·선별/발췌 방식도 바꾸지 않았다.

## 소프트웨어 검증

변경 전 전달 회귀 검사 4개 실패를 확인했다. 수정 후 실제 그래프를 사용하는 회귀 검사에서 의미 반려와 UNCLEAR, 두 번의 재계획에서 각 revision에 맞는 반려 계획 전달, 의미 반려 후 형식 오류에서 오래된 지적 제외를 확인했다.

`agent/python`에서 실행했다.

```sh
.venv/bin/python -m pytest -c pytest-v2-local-llm.ini -q
.venv/bin/ruff check src/kplasma_agent/v2_local_llm/graph.py src/kplasma_agent/v2_local_llm/core/contracts.py src/kplasma_agent/v2_local_llm/core/model_gateway.py tests/v2_local_llm/test_plan_review_graph.py tests/v2_local_llm/test_clone_boundary.py
```

pytest 760 passed·8 deselected. Ruff와 `git diff --check`도 확인했다. 고정된 초기 복제 자료는 수정하지 않았고 의도한 재계획 입력 차이를 복제 경계 기록에 명시했다.

## 웹 Q02 1회

동일한 원본 Q02를 새 대화에서 한 번 제출해 Qwen이 새 계획을 만들었다. 준비·실행 그래프 모두 `plan_review_enabled=true`, Docker VM 1536MiB, Qwen GGUF Q4_K_M·llama.cpp·24K 문맥·batch/ubatch256·생각 모드·캐시 OFF, d1 MLX Q8 단일·영어 compact·검사별 선별/발췌를 유지했다.

| 항목 | 수정 전 Q02 | 수정 후 Q02 |
|---|---|---|
| 최초 d1 계획 검토 | ISSUE | PASS |
| 재계획 | 2회 | 0회 |
| 실제 조건 조회 | 실행 전 차단 | 정확한 1개 결과 조회 |
| 답변 재작성 | 0회 | 1회 |
| 최종 응답 | 미완료 | PARTIAL |
| 기존 기준 최종 정답 | 실패 | 실패 |
| 전체 응답 시간 | 251.61초 | 154.79초 |

시간은 서버 접수부터 실행 종료까지다. Qwen이 매번 새 계획을 생성하므로 통제된 단일 변수 속도·정확도 개선율로 확대하지 않는다. 이번 계획은 조건별 구체적인 인용을 사용했고 세 숫자 검사 모두 match였다. 추가 설명 단계는 여전히 생성됐다. 설명문의 근거 참조에서 항목명 대신 실제 숫자를 넣은 오류가 최초 작성과 재작성에 반복돼 전체 완료가 되지 않았다. 조회값의 정확성과 최종 완료 여부를 구분했다. 답변 작성 오류는 이번 수정 범위에서 변경하지 않았다.

## 준비와 기록

계약 설명 변경으로 실행 준비 자료의 의존 파일 해시가 달라져 기존 증거를 수정하지 않고 메모리 검사를 다시 측정했다. 인공 준비 7/7 통과, 93표본, 관측 resident 피크17.921GiB, 경고0이었다. 실제 Q02 관측 피크는18.010GiB이며 경고0이었다.

준비용 모델 HTTP 요청은 메모리7회·평가 워커 연결4회·일반 워커 복귀4회로 웹 평가와 구분한다. Q02 품질 평가의 모델 요청은 최초 계획1·d1 계획 검토1·설명 작성1·재작성1이다. 추가 Q02 반복이나 다른 문항 평가는 하지 않았다.

이번에는 평가 중 실제 Qwen·d1 계획 검토 요청 본문을 Git 제외 로컬 폴더에 기록했다. 재계획이 없었으므로 실제 재계획 전송 원문은 생성되지 않았다. 평가 후 입력 기록용 워커를 종료하고 기록 기능이 없는 일반 워커로 복귀했다. 원시 질문·출력·점수·화면·준비 환경은 `.local/runtime/v2.5.1-replan-q02/`에 비공개로 보관한다.
