# LocalLLM_v2.3 체크포인트 — v2.4 시작 전 정리

2026-11-15. 기준 커밋은 `7803b297423b9f6002cf3031c7647a9ae13368a3`(LocalLLM_v2.1)이다. v2.2는 별도 커밋·태그 없이 이어서 개발된 작업 버전이므로, 이번 v2.3 체크포인트에는 **v2.2와 v2.3의 미커밋 변경을 함께 포함**한다. 실제 분리되지 않았던 v2.2 커밋을 소급해 만들지 않는다.

사용자의 최신 결정은 **영어화와 현재 v2.3 개선을 유지**하는 것이다. v2.4의 모델·엔진·지침 변경은 아직 시작하지 않는다. 과거 검증 문서는 각 측정 시점의 상태이며, 당시의 미커밋·실행 구성 설명을 현재 상태로 덮어쓰지 않는다.

## v2.2에서 포함되는 변경

- `requires`를 `required_prior_outputs`로 명확히 하고 필드별 설명·지시서·계획 검증·실행 바인딩을 정리했다. 과거 입력 alias는 읽되 저장된 기록을 덮어쓰지 않는다. backend의 과거/새 필드 원본 저장 호환성 검사도 포함한다.
- Qwen의 native `submit_plan` 계획/재계획 슬롯에 비공개 디스크 KV 저장·복원을 연결했다. 캐시 권한·경로·동일 설정·원자적 교체·복원 실패 처리·native 토큰 한도 검사를 유지했다.
- strict와 development 메모리 정책을 분리했다. 당시 Docker 2GiB에서 앞 5문항 캐시 OFF/ON 웹 비교 각 5/5 자동검사·UI 검사, 평균 전체 시간 96.992→68.250초를 관측했다. 이는 당시 캐시 적중 조건의 결과이며 현재 d1 구성의 웹 정확도를 뜻하지 않는다.

[선행 출력 필드](2026-11-14-local-llm-v2.2-prior-outputs.md), [캐시 구현](2026-11-14-local-llm-v2.2-qwen-plan-cache.md), [개발 정책과 OFF/ON 결과](2026-11-14-local-llm-development-memory.md)에 당시 실패·후속 통과·한계를 구분해 남겼다.

## v2.3에서 포함되는 변경과 실험

- Qwen의 native 입력 처리/생성·생각/도구 인자 분량·속도·진단 비용을 구분하는 수치 분석 경로를 추가했다. 생성 정책이나 응답 양식을 바꾸지 않았다.
- d1 MLX BF16 개별·공동 입력·독립4 후보를 비교했다. 공동 입력은 빨랐지만 정확도 관문에 실패했고, 독립4는 개별과 판정이 같아도 의미 있는 시간 이득이 없어 최종 경로에서 제거했다.
- d1을 같은 원본의 MLX 8비트로 변환했다. 모델 파일은 BF16 3.220GiB→Q8 1.940GiB다. 공식 readout이 사용하는 embedding은 BF16으로 보존했다. 실제 가중치·서비스·변환 helper·라이브러리와 준비 증거를 연결했다.
- 영어화·중복 축약·정리표 제외 단계의 5개 인공 계획 대조에서 Q8 기존 입력 대비 최종 검사당 토큰 19.59%, 검토 시간 19.35% 감소를 관측했다. 기대 상태는 3/5→2/5, 의도한 사유까지의 일치는 2/5→1/5로 낮아졌다. BF16 기준 행의 마지막 메타데이터 일치 검사 실패도 참고 측정의 한계로 보존했다.
- 이어서 두 사례 6회 분리 진단, 정상 5개/오류 5개의 5구성 50회 비교를 수행했다. 50회에서는 모든 구성의 기대 오류 항목·사유 적중이 0/5였다. 영어화만의 문제로 단정하지 않으며 현재 d1 검토 경로의 품질 문제를 미해결로 남긴다.
- 옛 d1 GGUF renderer/template/count 분기와 공동 입력/독립4 실행·평가 코드는 제거했다. **Qwen llama.cpp와 BF16 단일 경로는 유지**한다. 과거 원시 결과·실제 데이터·모델 파일은 삭제하지 않았다.

상태만 맞힌 건수를 올바른 오류 검출과 합치지 않는다. 모든 결과는 고정 인공 계획의 최초 검토이며 실제 Agent의 전체 웹 응답 성적이나 REPLAN 후 복구 성공률이 아니다.

## 체크포인트 검증

- Python 로컬 회귀·공통 응답 계약 659개 통과, 초기 복제 시점 전용 8개 제외.
- mypy: src와 MLX runtime/평가 포함 126개 소스 통과. 통합 검사에서 발견한 평가 스크립트의 메시지 타입 추론과 빈 클라이언트 정리 경로를 보완했다. 운영 그래프나 모델 입력 정책은 바꾸지 않았다.
- Node 로컬 실행/측정 스크립트 검사 8개 통과.
- Java21의 `AgentLocalGraphVersionTest` 1개 통과. 전용 Testcontainers 인공 DB에서 과거/새 계획 필드의 원본 저장을 확인했으며 실제 공용 DB를 사용하지 않았다.
- 변경 Python 범위 Ruff와 Git diff 검사가 통과했다. 공개 파일 guard도 통과했고, 검토한 88개 파일에 실제 env·모델·캐시·원시 평가·DB·Folio가 없는지 별도로 확인했다.

이번 정리에서는 실제 모델 평가를 추가하지 않는다. 실제 50회 측정의 메모리 warning 18표본·critical 0·swap 증가 830.69MiB와 현재 정상 복귀를 기록에 유지한다. 단순 연결·소프트웨어 검사 통과를 d1 의미 정확도 통과로 바꾸지 않는다.

## v2.4에 넘기는 미해결 사항

- 현재 d1 경로는 위 다섯 종류의 오류를 정확하게 검출하지 못했다. d1 모델 자체·입력 설계·MLX 수치 구현의 책임은 아직 분리하지 않았다.
- 공식 다른 추론 경로, 원본 정밀도, 다른 모델의 같은 사례 대조는 미실행이다.
- 전체 영어에서의 경향축 UNCLEAR와 단독 지침 영어에서의 기준 Run 오반려는 서로 다른 현상이다. 특정 문장이나 두 묶음의 결합 효과는 확정하지 않았다.
- 현재 Qwen 캐시 기본 OFF, 전체 40문항·장시간 운영·과학적 답변 수동 검토는 별도 검증 범위로 남는다.

위 항목은 인수인계 기록이며 v2.4 구현이나 추가 평가를 시작한 것이 아니다.
