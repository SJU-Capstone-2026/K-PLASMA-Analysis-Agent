# V3 검색 임베딩 후보 비교 (2026-11-15, 오프라인)

> **결정 (2026-11-15, 사용자 선택):** ko-sroberta와 엄격 거름망(a)을 `rules3-kosr` 엔진의 검색으로 채택했다. 전체 결정 기록은 [비교 실험 기록](../agent-v3-decision-engine-comparisons-20261115.md)에 있다. 실험 스크립트는 `agent/python/evals/v3_decision_engines/`(`embeddings.py`, `support_modes.py`, `encoders.py`)에 있다.

판단 기록 검색(RAG)의 임베딩 모델 후보 3개를 외부 모델 호출 없이 이 PC의 CPU에서 비교했다. 대상 데이터는 인공 메모 360건이다(서로 다른 문장 101개, 검색 문서 556개). 실제 물리 데이터와 사용자 판단은 사용하지 않았다.

## 후보

| 후보 | 저장소 · revision | 형식 | 크기 | 차원 | 최대 토큰 | 라이선스 표기 |

세 모델 모두 같은 int8 양자화 형식, mean pooling, L2 정규화를 사용했다. E5는 `query: `/`passage: ` 접두어를 사용하고 ko-sroberta는 접두어를 사용하지 않는다. 모델 파일 SHA256은 로컬 `.local/models/candidates.json`에 기록했다.

| 후보 | 맞춘 기준값 (dev→test / test→dev) | 교차 평가 종합 점수 | 정답 포함률 (상위 5개) | 정밀도 | 정답 없을 때 빈 결과 |

- **질문별 비교 (40개):**

### C. 명시 근거 거름망 방식 × 임베딩 후보

이 비교는 `RagService` 안의 명시 근거 선택(`assess_requested_evidence`)을 어떻게 적용할지에 대한 것이다. 세 방식 모두 범위·귀속 선택과 `index.search` 규칙은 동일하다. 기준값과 감점 크기는 dev/test 교차로 맞췄다.

| 방식 | 의미 |
| --- | --- |
| a 엄격 (현재) | 근거 표현이 없는 메모를 검색 전에 제거 |
| b 끔 | 거름망 없이 dense+lexical 검색만 사용 |
| c 약하게 | 제거하지 않고 dense 점수에서 감점(0.02~0.30 중 dev로 선택) |

| 조합 | 종합 | 정답 포함률 | 정밀도 | 정답 없을 때 빈 결과 | e5-small/a 대비 질문별 (나음/나쁨/같음) |
| --- | --- | --- | --- | --- | --- |
| e5-small / a (현재 PR #36) | 0.718 | 0.800 | 0.726 | 2/5 | - |
| e5-small / b | 0.578 | 0.657 | 0.549 | 2/5 | 3 / 13 / 24 |
| e5-small / c | 0.693 | 0.800 | 0.726 | 1/5 | 0 / 1 / 39 |
| e5-base / a | 0.720 | 0.771 | 0.703 | 3/5 | 9 / 6 / 25 |
| e5-base / b | 0.735 | 0.800 | 0.709 | 3/5 | 10 / 7 / 23 |
| e5-base / c | 0.740 | 0.829 | 0.749 | 2/5 | 7 / 5 / 28 |
| **ko-sroberta / a** | **0.782** | 0.800 | 0.760 | **4/5** | 8 / 4 / 28 |
| ko-sroberta / b | 0.753 | 0.829 | 0.777 | 2/5 | 9 / 8 / 23 |
| ko-sroberta / c | 0.728 | 0.800 | 0.749 | 2/5 | 8 / 8 / 24 |

- **거름망의 효과:** e5-small은 거름망을 끄면(b) 크게 나빠졌다(0.718 → 0.578). 작은 모델은 뜻이 반대인 메모를 구분하지 못해 거름망에 의존한다.
- **ko-sroberta에서 거름망을 끄면:** 정답 포함률과 정밀도는 약간 올랐지만, 정답 없는 질문에 빈 결과를 내는 수가 4/5에서 2/5로 줄었다.
- **Q13 "막 두께가 고르지 않아":** 모든 모델에서 거름망을 끈 경우(b)에만 성공했다. 거름망이 표현 차이로 정답을 지우는 사례다.
- **c(감점):** 어느 모델에서도 a나 b보다 뚜렷이 낫지 않았다. dev에서 고른 감점은 대부분 0.02~0.05로 작아서 b와 비슷하게 동작했다.
- 차이 대부분이 질문 몇 개 수준이므로 팀 평가셋으로 다시 확인해야 한다.

## 해석과 한계

- **순위 품질:** 임베딩만 비교하면 ko-sroberta가 가장 좋다. e5-base는 e5-small보다 나아지지 않았다.
- **차이가 작아지는 이유:** 실제 파이프라인에서는 질문의 절반 이상이 모든 모델에서 같은 결과를 냈다.
  - 임베딩 앞단의 규칙 기반 명시 근거 선택이 후보 문서를 먼저 정한다.
  - 예: Q13 "막 두께가 고르지 않아…"는 이 단계에서 문서가 0개가 되어 모든 모델이 실패했다.
  - 정답 없음 질문 중 Q36·Q38은 이 단계에서 문서가 0개가 되어 모든 모델이 성공했다.
- **표본이 작다:** 평가 질문이 40개뿐이다. 질문 하나가 2.5~5%p를 움직이며, 기준값을 맞추는 질문도 20개다.
- **정답지 편향:** 정답지는 인공 메모로 만든 초안을 일부 검토한 것이다. 팀 평가셋으로 다시 확인해야 한다.
- **ko-sroberta 제약:**
  - 최대 128토큰이라 긴 메모는 잘린다.
  - 모델 카드에 라이선스 표기가 없어 채택 전 확인이 필요하다.
  - 유사도 크기가 E5와 달라 기준값을 0.5 근처로 바꿔야 한다.
- **비용:** 외부 LLM 호출은 없었다.
