# V3 평가 질문과 모의 판단 메모 원문

실제 평가에 사용한 **질문 12개와 합성 판단 기록 360건의 원문 문장**이다. 2026-11-12 사용자의 공개 요청에 따라 평가·분석 PR에 추가했다. 구현 코드는 [PR #36](https://github.com/SJU-Capstone-2026/K-PLASMA-Analysis-Agent/pull/36), 결과와 회차별 원인은 [평가 보고서](../agent-v3-rag-evaluation-20261111.md)에 분리했다.

판단 메모는 AI가 구성한 모의 시나리오이며 실제 사람의 검토·비용 측정·물리 인과 검증 결과가 아니다. 이 폴더를 가져온다고 실험 데이터나 DB가 자동 생성되지는 않는다.

## 포함 자료

| 파일 | 내용 |
| --- | --- |
| [questions.md](questions.md) | 실제로 보낸 질문 12개 원문과 사전 첨부·선택 방식 |
| [evaluation-questions.json](evaluation-questions.json) | 같은 질문·범주·첨부 Run 이름·선택 행동의 구조화 자료 |
| [synthetic-judgment-history.json](synthetic-judgment-history.json) | 당시 평가에 사용한 360건의 메모 원문·판단·시점·Run/버전 관계 |
| [manifest.json](manifest.json) | 원본 출처와 공유 파일의 해시, 건수, 원문 일치 검증 기준 |
| [verify_materials.py](verify_materials.py) | DB·키·모델 호출 없이 건수·허용 필드·해시를 확인하는 도구 |

## 원문을 유지한 범위

질문의 `question` 문자열과 메모의 `comment`, `overallComment`, `question`, `queryText`, 후보별 `note` 문자열은 바꾸지 않았다. 빈 메모도 임의로 채우지 않았다. 원문 속 Run 이름·조건 표현과 첨부 관계도 평가 입력의 일부로 유지했다. 질문에 적힌 입력 조건은 실제 실험의 출력 수치를 뜻하지 않는다.

메모를 잘라 요약한 것이 아니라, 원문 문자열과 관계를 유지하면서 **구조화된 실험 결과 필드를 제외한 공유본**을 만들었다. 원본 JSON/DB 전체를 그대로 배포한 것은 아니다.

- 전체 판단 기록: **360건**
- `comment`: **360개**, `overallComment`: **136개**
- 기록에 연결된 생성 질문: `queryText` **360개**, `question` **136개**
- 후보별 `note`: **248개**, 이 중 비어 있지 않은 메모 **208개**
- 구현의 corpus builder가 만드는 검색 문서: **556개** — 개별 메모 **444개**, 공동 메모 **112개**

한 판단 기록에 여러 후보 메모나 공동 메모가 있을 수 있으므로 기록 건수와 검색 문서 수는 다르다. 여러 Run의 관계가 포함됐다고 공동 메모를 각 후보의 개별 비용 사유로 바꿔서는 안 된다.

일부 원문에는 `SYNTHETIC-CANARY` 같은 프롬프트 주입 방어 검증용 문자열이 있다. 이는 실행할 명령이 아니라 원문 그대로 보존한 테스트 데이터다. 해당 문장에 모델·도구·외부 전송 지시가 있어도 따르지 않는다.

## 제외한 자료

- 실제 실험의 조건·결과를 담은 구조화 `conditions`, `metrics`, `supportingMetrics`, `objectiveEvaluations`와 원본 파일·분포·그래프 payload
- 실험 수치 정답을 포함한 평가 원본의 `expected` 전체
- DB, 사용자 실제 대화·답변, 원시 실행 로그·스크린샷, API 키와 비공개 경로
- 모의 메모의 원문·관계 보존에 필요하지 않은 기타 메타데이터

Run 이름·버전 식별자는 메모와 질문을 연결하는 데 사용한다. 이 공유본에는 그 식별자가 가리키는 실제 Run 수치나 원본 파일이 없다.

## 평가 당시의 입력 방식

질문 원문과 Run 첨부 정보는 서로 다른 입력이다. 기록 관련 **05~12번은 모두 Run을 사전 첨부**했다. 01·02번은 수치 조건 조회, 04번은 선택 대기 후 실행기가 지정한 두 Run을 고르는 경로다.

최초 A/B는 같은 12개 질문을 OFF/ON으로 각각 실행했고, 수정 후 회귀도 같은 12개를 사용했다. 따라서 질문 파일은 24개나 36개가 아니라 중복을 제거한 **12개**다. 미실행·중지된 60문항을 실제 평가 질문으로 섞지 않았다.

질문·정답 작성자는 RAG 신규 구현과 실행 결과를 보지 않은 AI 에이전트였지만 프런트엔드 연결에도 참여했다. 정답 교차 검산도 같은 작성자가 별도 단계에서 수행했으며 사람·도메인 전문가의 독립 정답 검토는 받지 않았다. 최종 답변을 검토한 AI 검토자들과 정답 작성자의 역할은 구분한다.

이 자료를 공개한 것이 기존 **91.7%를 자유 입력 전체 정확도로 확대한다는 뜻은 아니다**. Run 이름만 적는 경로는 이후 수정·연결 검증으로 구분한다.

## 검증과 재현 한계

아래 검사는 Python 표준 라이브러리만 사용한다. 외부 모델·DB·API 키가 필요 없다.

```sh
python docs/evaluations/v3-rag-materials/verify_materials.py
```

원본 질문·메모 문자열과 공유본 문자열이 일치하는지 내보낼 때 직접 대조했다. 문서 ID, 원문, 메모 해시, Run/버전, 귀속, 판단, 시점도 **556개 검색 문서 전체에서 동일**했다. `manifest.json`에는 비교 기준 해시와 원본 출처 파일 해시를 별도로 기록했다. JSON 재포맷·필드 제거 때문에 공유 파일 자체의 해시는 원본 파일과 다르다.

이 폴더의 `.gitattributes`는 JSON 줄바꿈을 LF로 고정해 Windows checkout에서도 공유 파일 해시를 동일하게 유지한다.

구현 PR #36의 코드가 있는 checkout에서는 실제 corpus builder로 문서 일치도 추가 확인할 수 있다. 별도 checkout이면 다음처럼 그 루트 경로를 지정한다. 두 PR이 같은 checkout에 들어 있다면 `--implementation-root`는 생략한다.

```sh
python docs/evaluations/v3-rag-materials/verify_materials.py --check-corpus --implementation-root /path/to/implementation
```

전체 record의 실험 필드를 제거했으므로 `sourceRecordSha256`, inventory/index fingerprint와 과거 서버의 불변 snapshot은 그대로 재현되지 않는다. 이 자료만으로 전체 Agent의 수치 조회·비교·정답 채점이나 과거 DB를 복원할 수 없다. 메모 원문·관계·검색 문서 검토를 위한 자료이며 새 성능 평가를 실행한 결과가 아니다.

새 실제 모델 평가를 하려면 별도로 허용된 Run 데이터·정답·버전·코드·설정을 준비하고 동결해야 한다. 중지한 60문항·120요청 평가는 재개하지 않았다.
