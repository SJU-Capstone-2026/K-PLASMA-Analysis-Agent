# Agent v2 CI 전환 구현 계획

> 실행: 현재 대화에서 승인한 기존 v2 코드와 CI 통합 PR을 준비한다.

**목표:** main에서 빠진 기존 v2 화면·채팅·계획 검토 코드를 통합하고 기본 Agent 실행 검증과 브라우저 검증을 v2로 전환한다.

**구조:** 기존 v2 그래프, 고정 모델 worker, Playwright 시나리오와 격리 DB 실행기를 재사용한다. 공통 수치·입출력·저장·보안 검증은 유지하며 v1 전용 그래프·fallback 평가와 브라우저 실행은 기본 CI에서 제외한다.

**기술:** Python/pytest, Node, Playwright, Spring/Gradle, GitHub Actions. 의존성 추가 없음.

**기준:** `docs/superpowers/specs/2026-11-01-agent-v2-contracts.md`, `docs/development/agent-v2.md`, 사용자 요청.

## 제약과 검토 초점

- main 직접 변경·push·병합 없이 별도 PR로 제출한다.
- 기존 제품 동작·기록 형식·모델 기본값은 변경하지 않는다.
- 인공 데이터만 사용한다. API 키·실데이터·답변 원문·trace를 저장소/Actions artifact에 게시하지 않는다.
- 실제 LLM 호출은 사용자가 별도로 요청해 실행하는 기존 명령으로 남긴다. 수동 Actions 추가 여부는 사용자 답변 전까지 확정하지 않는다.
- v1 기록 읽기와 공통 API·계산 회귀 검사는 호환성을 위해 유지한다.
- 선택 전후 계획 재검토, 엄격한 `>` 경계, 선택한 Run 버전, 중복 재개, 재시작 후 체크포인트를 검사한다.

## 1. 기존 v2 코드 통합

- `origin/main`에서 `test/agent-v2-ci`를 만들고 `origin/feat/agent-v2-chat-ux`를 통합한다.
- #24–26 변경을 재구현하지 않는다. 미완성 #27/#29 판단 기록 기능은 추가하지 않는다.
- 확인: 원격 main과의 이력, 충돌, diff, 기존 v2 계약·그래프 검사.

## 2. 기본 CI·브라우저 대상 전환

- 변경: `.github/workflows/ci.yml`, `package.json`, `agent/package.json`.
- 추가: `agent/python/pytest-v2.ini`, `frontend/agent-v2-ui.playwright.config.ts`.
- 변경: `scripts/agent/verify-v2.mjs`, `frontend/e2e/agent-v2-live.spec.ts`.
- 기본 Python 대상은 v2 그래프·평가기 및 공통 계산/스트리밍/관찰 검사로 명시한다.
- 기본 E2E와 live 명령은 v2만 실행한다. live에서도 잘못된 후보·실패 상태는 실제 실패 처리한다.
- UI는 기존 v2 비교 그래프, 대화방·Run 태그, 진행·스트리밍·재연결·취소 시나리오를 재사용한다.
- 확인: pytest/Playwright 수집 목록에 v1 전용 실행이 없고 390/800/1008/1440px v2 검사가 포함된다. 타입·lint·build도 실행한다.

## 3. v2 재시작 검증과 문서

- 변경: `scripts/agent/restart-verification.mjs`, `README.md`, `docs/development.md`, `docs/development/agent-v2.md`.
- `graphVersion: v2` 요청과 `runtime_v2_worker.py`를 사용한다.
- 검증: QUEUED 서버 재시작, 선택 대기 worker/서버 재시작과 고정 선택지, 선택 재개 후 비교→max→검색 결과, 완료 후 동일 키 재개와 대화 스냅샷·revision 보존.
- 기존 격리 DB/서버 실행기를 쓰고 실패는 비정상 종료한다.
- CI의 고정 모델 검증과 실제 LLM 판단 평가의 차이·실행 명령·제한을 문서화한다.

## 4. 검증과 PR

- Python v2와 공통 검사, frontend/agent 단위·타입·lint·build, v2 UI Playwright를 로컬 실행한다.
- Docker/Java 21이 없는 로컬의 DB 종단·재시작 검증은 GitHub Actions의 실제 결과로 확인한다.
- 변경분 리뷰 후 PR을 열고 CI를 확인한다. 사용자가 main 병합을 담당한다.
